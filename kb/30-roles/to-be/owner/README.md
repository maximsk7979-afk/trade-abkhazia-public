# Владелец (`owner`)

> Минимальное описание суперроли — закрывает белое пятно аудита 2026-06-11 («owner — суперюзер,
> но как роль не описан»). Полные процессы владельцу не нужны: он — высшая инстанция всех
> чужих процессов, а не исполнитель собственных.

## Держатель

**Максим Скороходов** (С-001, tgChatId 118206343). Единственный носитель роли по определению.

## Суть роли в RBAC (ADR-022)

- **Суперюзер, fail-open для себя**: `roleAllowed` пропускает owner к ЛЮБОМУ инструменту
  Евы и любым данным — гейтинг по ролям его не ограничивает.
- **Эксклюзивные права** (не делегированы даже ГД): смена **якоря** бананового прайса
  (ADR-020); включение авто-kickoff закупки (`PROCUREMENT_KICKOFF_ENABLED`); решения о
  ролях сотрудников (назначение через карточки staff).
- **Верхняя эскалация**: все таймауты оркестратора закупки (ГД молчит, проезд не подтверждён),
  алерты бюджета Bedrock (GAP-026 A), health-алерты Евы (GAP-046), уведомления о новых
  клиентах/заявках — приходят владельцу.

## Чем владелец пользуется

- **Ева** — управление прайсами (`manage_banana_pricing` — якорь; weighted), все staff-сценарии.
- **trade_app** — всё.
- **Уведомления** — Telegram (NOTIFY_CHAT_IDS).

## Что НЕ делает (по модели)

Операционные шаги процессов закреплены за ролями (ГД/закупщик/менеджер/экспедитор) — владелец
может вмешаться везде, но процессы спроектированы так, чтобы это требовалось только на
эскалациях. AS-IS (2026): владелец фактически совмещает закупщика — см. as-is/.
