# Процесс: отгрузка и доставка

> Бизнес-процесс роли [экспедитора](../README.md). Описывает, **что происходит** от готовой заявки до состоявшейся продажи с точной суммой и оплатой. Жизненный цикл статусов — [sales-lifecycle.md](../../../../20-domain/sales-lifecycle.md); формулы весов — [weight-calculation.md](../../../../20-domain/weight-calculation.md); формат `items[]`/`shipment[]` — [sale.md](../../../../40-system/data-formats/sale.md); модель продаж — [ADR-007](../../../../90-decisions/ADR-007-sales-canonical-model.md).
>
> Сейчас роль совмещает менеджер ([GAP-013](../../../../00-meta/gaps.md#gap-013)); фиксация — в trade_app (модуль «🚚 Доставки»).

## Кратко

Заявки, готовые к отгрузке (ЗР «На складе», ЗД «Новая»), собираются в **доставку** (Д-XXX). Машина загружается («Выехали»), товар списывается со склада по FIFO. У клиента экспедитор фиксирует **факт отгрузки**: весовые позиции **взвешиваются у клиента** (тар × брутто → нетто), тарные — по количеству; цена по умолчанию — **замороженная согласованная** при заказе. Считается `shipmentTotal`, принимается оплата (`shipmentPaid`), заявка → «Отгружено» — это **состоявшаяся продажа**. Непроданный остаток возвращается на склад при завершении доставки.

## Действующие лица

- **Экспедитор** — собирает доставку, везёт, выдаёт, взвешивает, принимает оплату, фиксирует факт и возвраты. *(Сейчас — менеджер в совмещении.)*
- **Менеджер продаж** — обеспечивает корректные заявки; обрабатывает последствия (долг, недостача).
- **Клиент** — принимает товар, оплачивает.
- **Ева** — уведомляет; в перспективе — мобильная фиксация и фото накладной ([GAP-020](../../../../00-meta/gaps.md#gap-020)).

## Предусловие: заявка готова к отгрузке

- **ЗР** (под рейс) доходит до статуса **«На складе»** через каскад рейса (рейс: Планируется → В закупке → В пути → На складе — см. [sales-lifecycle.md §2](../../../../20-domain/sales-lifecycle.md)). Для **ежедневного смешанного рейса** ([ADR-021](../../../../90-decisions/ADR-021-daily-mixed-trips-day-order.md)) рейс создаётся лениво при первом заказе и проводится по статусам в админке trade_app.
- **ЗД** (с нашего склада) готова в статусе **«Новая»**.

## Шаги процесса

| # | Кто | Действие | Правило |
|---|---|---|---|
| 1 | Экспедитор | **Создаёт доставку** Д-XXX, выбирает заявки из пула (ЗР «На складе» / ЗД «Новая») | Можно несколько клиентов в одной доставке |
| 2 | Экспедитор | (Опц.) Добавляет **доп. объём** сверх заявок | Берётся из складского остатка; для допродажи у клиента |
| 3 | Экспедитор | **«Выехали — загрузить и отправить»** | Доставка → «В пути»; все заявки → «В доставке»; FIFO списывается (`WhOp` shipment) |
| 4 | Экспедитор | У клиента: **взвешивает весовые** (тар × брутто) | `netto = Σбрутто − Σтар × tw`; точная сумма строки = `netto × цена` |
| 4т | Экспедитор | Тарные (банан и т. п.): указывает **количество упаковок** | Сумма строки = `qty × цена` |
| 5 | Экспедитор | (Опц.) **Допродажа** из свободного объёма | Отдельная строка отгрузки сверх заявки |
| 6 | Экспедитор | Принимает **оплату**, фиксирует `shipmentPaid` | Недоплата → долг клиента; переплата → предоплата |
| 7 | Экспедитор | **«✅ Отгружено»** по клиенту | Заявка → «Отгружено»; пишутся `shipmentTotal`, `shipmentPaid` (это **состоявшаяся продажа**) |
| 8 | Экспедитор | После всех клиентов — **«Завершить доставку»** | Непроданный остаток → возврат на склад (FIFO восстанавливается); фиксируются расходы доставки |

## Цена при отгрузке (важно)

- **По умолчанию — замороженная согласованная цена**, с которой клиент оформлял заявку (хранится в `miniOrder.lines[].unitPrice`): для весовых — ₽/кг, для банана — ₽/ящик. Это гарантирует, что **точная сумма после взвешивания** считается по той цене, о которой договорились ([GAP-038](../../../../00-meta/gaps.md#gap-038)).
- Если у заявки нет замороженной цены (создана вручную, не из мини-аппа) — подставляется цена из прайс-листа клиента.
- **Экспедитор может изменить цену строки** у машины (рынок сильно двинулся / договорённость на месте). Крупные отклонения — согласование с владельцем/менеджером.

## Взвешивание весового товара (у клиента)

- Взвешивают **у клиента при выдаче** (решение 2026-06-06) — это даёт **факт-вес** и точную сумму.
- Каждое взвешивание = `тар (число упаковок) × брутто (кг)`. Несколько взвешиваний суммируются.
- `netto = Σбрутто − Σтар × tw` (`tw` — вес одной тары из справочника SKU). Защита `max(0, …)`.
- До отгрузки клиент видел **ориентировочную** сумму (теор. вес `qty × (gw − tw)`); после фиксации факт-веса мини-апп показывает **точную** (`shipmentTotal`).

## Результат процесса

- Заявка (ЗР/ЗД) → **«Отгружено»**: проставлены `shipmentTotal` (факт) и `shipmentPaid`.
- Баланс клиента обновлён (долг/предоплата); мини-апп клиента показывает точную сумму.
- Непроданный остаток вернулся на склад; расходы доставки учтены.

## Отложенные ситуации (не в этом процессе)

- **Частичная нехватка на рейсе** — кому резать объём ([GAP-031](../../../../00-meta/gaps.md#gap-031)).
- **Брак / возврат скоропорта при доставке** — пересчёт суммы и баланса ([GAP-032](../../../../00-meta/gaps.md#gap-032)).
- **Фото отгрузочной накладной + распознавание через Еву** ([GAP-020](../../../../00-meta/gaps.md#gap-020)).
- **Учёт смешанного рейса по проектам** (per-line projectId, FIFO, аллокация расходов) — «Шаг 3» ([GAP-041](../../../../00-meta/gaps.md#gap-041)).
