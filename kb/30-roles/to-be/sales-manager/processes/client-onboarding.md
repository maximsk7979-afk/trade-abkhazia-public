# Процесс: завод нового клиента

> Бизнес-процесс роли [менеджера продаж](../README.md). Описывает, **что происходит** при заводе нового клиента. Техническая сторона Евы (диалог, инструменты, краевые случаи) — в сценарии [eva/scenarios/client-onboarding.md](../../../../50-agents/eva/scenarios/client-onboarding.md). Поля карточки — [ADR-014](../../../../90-decisions/ADR-014-client-project-profile.md).

## Кратко

Менеджер заводит нового клиента **диалогом с Евой**: инициирует свободной фразой → Ева ведёт опрос «один вопрос = одно поле» с проверкой каждого ответа → в конце выдаёт отчёт по карточке и ссылку-приглашение. Клиент **активен сразу** после завода. Если у клиента есть Telegram — менеджер пересылает ему ссылку, клиент жмёт «Старт», и Ева привязывается к его Telegram для дальнейшего общения.

## Действующие лица

- **Менеджер продаж** — инициирует и проходит опрос.
- **Ева** — ведёт опрос, создаёт карточку, выдаёт ссылку.
- **Клиент** — (если есть Telegram) активирует приглашение.

## Запуск

Менеджер пишет Еве **любой фразой по смыслу**: «новый клиент», «давай заведём клиента», «надо добавить покупателя». Жёстких команд нет — Ева понимает намерение. Ева подтверждает: «Ок! Начинаем завод нового клиента» — и начинает опрос.

## Опрос: один вопрос = одно поле

Ева задаёт вопросы по очереди. Следующий вопрос — только когда текущий ответ её **устроил** (прошёл проверку). Поля-выбор — кнопками; свободный текст — сообщением.

| # | Поле | Вопрос Евы | Ввод | Проверка / правило |
|---|---|---|---|---|
| 1 | Название клиента (`n`) | «Название клиента (магазин/компания)?» | текст | **уникально** в базе; дублей нет |
| 2 | Контактное лицо (`contactName`) | «С кем общаемся? Имя контактного лица?» | текст | обязательно; уникальность не нужна. Этим именем Ева обращается к клиенту |
| 3 | Проекты (`projectId`×N) | «По каким проектам работаем?» | кнопки-галочки, **мультивыбор** | только **активные** проекты; выбран ≥1 |
| 4 | Сегмент (`segment`) | «Сегмент клиента?» | кнопки, 1 выбор | **один на клиента**; список = сегменты, подходящие **всем** выбранным проектам (пересечение); обязательно |
| 5 | Уровень цены (`priceLevel`) | «Уровень цены — опт / ср.опт / розница?» | кнопки, 1 выбор | **один на клиента**; обязательно |
| 6 | Тип продажи (`saleType`) | «Самовывоз (ПС) или доставка (ЗД)?» | кнопки, 1 выбор | **один на клиента**; обязательно |
| 7 | WhatsApp (`wa`) | «Телефон/WhatsApp клиента?» | текст | **обязательно**, международный формат `+<код>` |
| 8 | Яндекс-навигатор (`ynavUrl`) | «Ссылка на точку в Яндекс.Навигаторе?» | текст | Ева **предлагает**, можно пропустить |
| 9 | Фото места (`locationPhotos[]`) | «Пришлите фото места доставки (вход, витрина, ориентир)» | фото (1+) | Менеджер шлёт фото — Ева сохраняет в `client.locationPhotos[]` через `POST /api/photos`. Можно прислать несколько (по одному или альбомом) и можно пропустить текстом. После реализации Блока 1 [GAP-018](../../../../00-meta/gaps.md#gap-018) (база `client-locations` фото-инфраструктуры, [ADR-016](../../../../90-decisions/ADR-016-photo-infrastructure.md)). До реализации — Ева пропускает шаг |

**Заполняются без вопросов:**
- **Менеджер** (`managerId`) — авто = сам спрашивающий (Ева знает его по `telegramChatId`). Смена менеджера — через веб-приложение.
- **Telegram username** (`tg`) и **chat ID** (`tgChatId`) — авто при активации приглашения (если у клиента есть Telegram).
- **Статус** (`onbStatus`) — `Активен` сразу при заводе.

> Сегмент/цена/тип продажи хранятся в каждом проектном блоке клиента (ADR-014), но на онбординге задаются **по одному ответу** и пишутся одинаково во все блоки.

## Прерывание

Менеджер в любой момент может прервать («стоп», «отмена», «не сейчас») — Ева сворачивает завод **без сохранения** карточки.

## Завершение: отчёт и приглашение

Когда все обязательные поля заполнены, Ева выдаёт отчёт:

> «Завела — *Магазин «Морской»* (К-026), контакт Аршак, опт, проекты: местные + грузинские овощи, сегмент магазин, доставка, менеджер ты. Вот ссылка-приглашение, отправь клиенту в WhatsApp: `t.me/<eva_bot>?start=onb_a7f3`. Как нажмёт — подхвачу.»

Менеджер **сам пересылает** ссылку клиенту в WhatsApp (Вариант 1; автоотправка через WhatsApp Business API — будущая опция, см. [roadmap](../../../../65-roadmap/current.md)).

## Активация (если у клиента есть Telegram)

Клиент жмёт ссылку → «Старт» → Ева привязывает его `tgChatId` (и `tg`, если есть username), может с ним переписываться. **Telegram не обязателен**: без него клиент всё равно активен, просто без канала Евы.

## Статусы клиента (`onbStatus`)

- **Активен** — клиент в работе (сразу после завода).
- **На паузе** — временно отключён (по решению менеджера, через веб).

Промежуточного «черновика» нет: завод и активность — один момент.

## Результат процесса

- Создана карточка клиента (`К-XXX`), `onbStatus=Активен`, привязана к менеджеру.
- Если есть Telegram и клиент активировал — связка `tgChatId ↔ клиент` установлена, заведена память клиента (слой B).

## Текущий путь (до запуска Евы)

Пока сервис Евы ещё не реализован, клиента можно завести через **форму trade_app** (Справочники → 👥 Клиенты → «+ Клиент»). Та же валидация (уникальное имя, обязательное контактное лицо, проектные блоки) работает в форме. После запуска рантайма Евы основной путь — диалог в Telegram; форма остаётся доступной для правок и для случаев, когда менеджер сам не работает в Telegram.
