# Конвенции

Правила именования, структура файлов, формат метаданных.

## Имена файлов и папок

- **kebab-case**: маленькими буквами через дефис. `liya-partner.md`, `pricing-rules.md`.
- **Только латиница**, цифры и дефисы. Никакой кириллицы, пробелов, заглавных букв.
- **Расширение** `.md` для документации. Шаблоны — тоже `.md`.

## Нумерованные префиксы папок

Слои `kb/` пронумерованы (`00-meta/`, `10-business/`, `20-domain/`, ...). Префиксы:
- задают порядок сортировки
- между числами оставлены промежутки — можно вставить новый слой без переименования

## Front matter

Каждый `.md`-файл начинается с YAML-блока:

```yaml
---
title: Человекочитаемое название
status: active | draft | archived
last_updated: YYYY-MM-DD
data_source:                # опционально, если данные из БД
  type: database
  storage_key: trade-cat-staff
  staff_id: С-002
references:                 # на какие файлы ссылается
  - 20-domain/sales.md
referenced_by:              # какие файлы ссылаются на этот
  - 30-roles/owner.md
related_decisions:          # связанные ADR
  - ADR-005-pricing-rules.md
---
```

Поля `references` / `referenced_by` ведёт CC автоматически (см. [maintenance.md](maintenance.md), Обязательство 2).

## Заголовки

- `#` — название файла, **один на файл** (тот же текст, что в `title`)
- `##` — основные разделы
- `###` — подразделы
- глубже не идём; если нужно `####` — файл слишком большой, делим

## Даты

Везде формат `YYYY-MM-DD` (`2026-04-28`). ISO-стандарт, однозначно сортируется.

## Ссылки

- Внутренние — относительные пути: `[Текст](../20-domain/pricing.md)`
- Внешние — явно: `[GitHub Docs](https://docs.github.com)`

## Длина файла

- Целевая: 200-400 строк
- 600+ — сигнал, что пора делить

## Правило для глоссария

⚠️ **`00-meta/glossary.md` содержит только короткие определения** (1-3 предложения на термин) + ссылки на доменные/системные файлы.

**Что НЕ кладём в глоссарий**:
- Полные таблицы полей сущностей → `40-system/data-formats/<entity>.md`
- Алгоритмы (каскады статусов, FIFO-распределение, расчёт прайса) → `20-domain/<topic>.md`
- Подробные правила бизнес-логики → `20-domain/`
- Реализационные детали (имена функций, номера строк кода) → `40-system/`

Это нужно, чтобы:
- Глоссарий оставался **стабильным** (меняется редко, только при появлении/уточнении терминов)
- Не нарушался [Single Source of Truth](../90-decisions/ADR-002-modular-knowledge-base.md) — если правила меняются, правка идёт **в одном** доменном файле, не в двух
- Глоссарий быстро читался при первом знакомстве с проектом

**Шаблон карточки термина**:
```markdown
### Название термина (англ.)
Краткое определение в 1-3 предложения. Где хранится / как ID формируется (если применимо).

Полное описание (если есть): [ссылка на доменный файл](...).
```

**Запрет на имена и оперативные данные в глоссарии**:
- ❌ Нельзя в карточке роли указывать конкретных людей ("Сейчас один — Максим Скороходов (С-001)")
- ❌ Нельзя перечислять конкретные ID контрагентов ("Текущие водители: Джамна (КА-007), Тэриэл (КА-008)")
- ✅ Описывать **роль/сущность как абстракцию** — что делает функция в принципе, без привязки к носителям

Причина: фамилии, имена и ID — оперативные данные. По [ADR-004](../90-decisions/ADR-004-data-source-of-truth.md) их источник истины — БД (`trade-cat-staff`, `trade-cat-contragents`). Дублирование в глоссарии гарантированно устаревает при кадровых изменениях.

Где допустимы имена:
- В [`15-team/<person>.md`](../15-team/) — заметки о конкретных людях
- В ADR (исторический контекст: "решение принято с участием X")
- В CHANGELOG (хроника изменений)

## ID и префиксы сущностей

Сохраняются в исходных формах из системы:
- `ПС-XXX`, `ДС-XXX` — продажи
- `Р-XXX` — рейсы
- `Д-XXX` — доставки
- `B-XXXX` — партии
- `К-XXX` — клиенты
- `КА-XXX` — контрагенты
- `П-XXX` — поставщики
- `С-XXX` — сотрудники
- `Т-XXX` — товары
- `О-XXX` — офисы
- `SKU-XXX-XX` — единицы хранения
- `INC-XXX` — инциденты
- `ADR-XXX` — решения

## Стиль текста

- Без воды и литературного стиля
- Конкретно, по делу
- Эмодзи — только в `INDEX.md` для разделов и в `glossary.md` для категорий. В обычных файлах — не используем

## Кодовые блоки

Всегда указываем язык:

````markdown
```javascript
const x = 1;
```
````

## Что НЕ кладём в репо

- Пароли, API-ключи, токены
- Реальные финансовые цифры (это БД)
- Персональные данные (паспорта, адреса)
- Любую информацию, утечка которой нанесла бы ущерб

См. также [.gitignore](../../.gitignore).
