# Шаблон ТЗ от Архитектора

Полусвободный формат: секции стандартные, содержание произвольное.

---

## Структура

```markdown
# Задача: [короткое название]

## Контекст
2-4 строки: почему задача появилась, какая проблема решается.

## Цель
Что должно получиться (одно предложение).

## Релевантные файлы kb/
- `kb/<путь>` — какое отношение имеет
- ...

## Требования
1. ...
2. ...

## Что НЕ входит в задачу
- ... (явное исключение)

## Открытые вопросы
- (если есть — для CC или для Максима; иначе пропустить секцию)

## Приоритет
high / medium / low

## Формулировка от
Архитектор
```

## Пример заполненного ТЗ

```markdown
# Задача: Описать роль "Кладовщик" в TO-BE

## Контекст
В команде есть сотрудник с ролью warehouse (Саид, С-005), который совмещает её с sales-manager. При проектировании Евы нужно описать кладовщика как отдельную TO-BE-роль, чтобы Ева могла поддерживать его сценарии работы (приёмка по приходу рейса, формирование загрузки, оприходование возвратов, ежедневная инвентаризация).

## Цель
Создать `kb/30-roles/to-be/warehouse.md` по шаблону роли с описанием функций кладовщика для целевой архитектуры.

## Релевантные файлы kb/
- `kb/30-roles/README.md` — карта ролей и трансформации
- `kb/00-meta/templates/role-template.md` — шаблон роли
- `kb/00-meta/glossary.md#кладовщик-warehouse` — функция уже описана
- `kb/20-domain/sales-lifecycle.md` — как кладовщик связан со статусами

## Требования
1. Использовать шаблон `role-template.md`
2. Описать обязанности из глоссария + детализировать сценарии:
   - Приёмка товара по приходу рейса (статус "На складе")
   - Формирование загрузки доставки (статус "В пути")
   - Оприходование возвратов с доставки
   - Ежедневная инвентаризация
3. Указать связи с другими ролями: sales-manager, экспедитор
4. В разделе "Использует функции системы" перечислить модули
5. В разделе "Сценарии Евы" — что Ева делает для кладовщика

## Что НЕ входит в задачу
- AS-IS-описание (это отдельная задача)
- Реализация UI или RBAC (это код, потом)

## Открытые вопросы
- Стоит ли упомянуть совмещение с sales-manager как опцию или это только текущая ситуация?

## Приоритет
medium

## Формулировка от
Архитектор
```
