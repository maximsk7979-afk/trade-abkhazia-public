# Белые пятна (gaps)

Очередь обнаруженных пропусков в документации. Реализация Обязательства 4 из [контракта CC](maintenance.md).

## Формат записи

```markdown
### GAP-NNN: <короткое описание>
**Обнаружено**: YYYY-MM-DD
**Где**: путь к коду / модулю / месту в системе
**Суть**: что именно не описано
**Приоритет**: high / medium / low
**Статус**: open / in-progress / closed (с датой и ссылкой на ADR/файл)
```

### GAP-009: Закупка вне рейса не описана и не реализована
**Обнаружено**: 2026-04-28 (при наполнении глоссария)
**Где**: текущая модель закупок завязана на `trip.items[]`. Закупка вне рейса — отсутствует.
**Суть**: Местные и российские поставщики продают товар **не через рейс из Грузии**. Сейчас в системе нет flow "приход на склад от местного поставщика без рейса". Возможные пути:
- Создать "виртуальный рейс" с одним поставщиком и без расходов рейса (плохо — путает понятие рейса).
- Ввести **отдельную сущность "Поступление" / "Закупка"** (Purchase / Receipt), не привязанную к рейсу. Тогда `Trip` остаётся для грузинской логистики, а `Purchase` для всего остального.
- Расширить `WhOp` типом `"income"` с указанием поставщика, цены, валюты — приход на склад напрямую.

**Приоритет**: high (нужно для местных поставщиков, которые уже есть)
**Статус**: open. Требуется архитектурное решение → ADR, потом реализация.

**Дополнительно (от Максима 2026-04-28)**: при реализации этой функции **доработать правило учёта себестоимости**. Для местных поставщиков `costPU = закупочная цена в RUB` без долей `expShare` рейса (которых нет). Возможны свои расходы (доставка от местного поставщика на склад) — их надо ввести отдельным механизмом или включить в цену.

### GAP-012: Стоимость списаний не учитывается как отдельная финансовая статья
**Обнаружено**: 2026-04-28 (при наполнении глоссария, карточка "Списание")
**Где**: `trade_app_v3.jsx`, обработка `whOp.opType === "writeoff"`. Списание уменьшает физический остаток в FIFO-партии, но **не порождает** запись в финансовом учёте о потерях.
**Суть**: Когда товар списывается на брак/порчу/утрату, **деньги, потраченные на его закупку, исчезают** из учёта без следа. То есть мы видим уменьшение остатка, но **не видим**:
- Сколько денег "сгорело" на списаниях за период
- Какие товары чаще списываются (частая порча → плохой поставщик / плохие условия хранения / неправильная закупка)
- Влияние списаний на общую прибыль

В коде каждая partia (`batch`) знает свою себестоимость единицы (`costPerUnit`), значит, в момент списания **можно вычислить стоимость списанного** = `qty × batch.costPerUnit`. Но эта величина никуда не сохраняется.

**Приоритет**: medium (нужно для финансовых отчётов, отчётов о потерях, P&L)
**Статус**: open. Что нужно:
- При создании whOp типа `writeoff` дополнительно сохранять рассчитанную стоимость списания (поле `writeoffCost` или подобное)
- Добавить в финансовые отчёты строку "Потери от списаний"
- Добавить отчёт "Списания за период" с детализацией по товарам/SKU
- Возможно — категории причин списания (испортилось / разбилось / утрачено / иное), для аналитики

### GAP-007: Разделитель дробей — запятая не работает (CLOSED)
**Обнаружено**: 2026-04-28 (при разборе раздела 8 CONTEXT.md)
**Где**: `trade_app_v3.jsx`, функция `pN(s)` (строка ~172) и `fmt(n)` (~174)
**Суть**: `parseFloat("5,8")` возвращал `5`, теряя дробную часть. CONTEXT.md заявлял, что запятая и точка равнозначны.
**Приоритет**: medium → **closed**
**Статус**: ✅ closed 2026-04-28. Исправлено в коде, развёрнуто на VPS:

```javascript
function pN(s) {
  if (typeof s === "string") s = s.replace(",", ".");
  return parseFloat(s) || 0;
}
function fmt(n) {
  var v = (typeof n === "string") ? parseFloat(n.replace(",", ".")) : parseFloat(n);
  ...
}
```

Теперь и `pN("5,8") === 5.8` ✅, и `pN("5.8") === 5.8` ✅. Поведение соответствует требованию CONTEXT.md.
