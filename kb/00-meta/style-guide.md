# Стиль написания документации

Правила того, **как** мы пишем тексты в `kb/`. Структуру и именования см. в [conventions.md](conventions.md).

## Язык

- **Основной язык — русский.**
- **Технические термины** — английские, если у них нет устоявшегося русского аналога (`API`, `JWT`, `front matter`, `runbook`, `passkey`).
- **Идентификаторы и имена в коде** — английские (`saleType`, `officeId`).
- **Имена файлов** — английские (см. [conventions.md](conventions.md)).

## Стиль

- **Бизнес-часть** — понятно, доступно. Нелли должна понять.
- **Техническая часть** — формально, точно. Не теряет точность ради простоты.
- **Без литературщины**: не "посредством", не "представляется целесообразным". "Через", "лучше".
- **Активный залог**: не "файл создаётся скриптом", а "скрипт создаёт файл".
- **Конкретно**: не "много ошибок", а "27 рестартов за 32 дня".

## Заголовки

- Не дублируй слова из контекста. В файле `pricing.md` заголовок `## Правила формирования прайса`, а не `## Прайс`.
- Не используй вопросительные ("Что такое прайс?") — используй утверждения ("Правила прайса").
- Не используй точки в конце.

## Списки

- **Маркированный** (`-`) — для перечисления равнозначных вещей.
- **Нумерованный** (`1. 2. 3.`) — для шагов в последовательности или порядка важности.

## Таблицы

Используй для:
- сравнения 2+ вариантов
- матриц "роль × право"
- параметров с несколькими атрибутами

Не используй для:
- 2-3 простых пунктов (это маркированный список)
- одной колонки (это перечисление)

## Ссылки на сущности

- На термины из глоссария — линкуй в первый раз: `[ДС](../00-meta/glossary.md#дс-продажа-доставки)`
- На бизнес-правила — линкуй на файл правила
- На решения — линкуй на ADR

## Кодовые блоки

Указывай язык — это включает подсветку и помогает ИИ:

````markdown
```javascript
const x = 1;
```

```sql
SELECT * FROM app_storage;
```

```bash
pm2 list
```

```json
{"id": "ПС-087"}
```
````

## Цитаты и предупреждения

- Используй `>` для пометок: `> ⚠️ Внимание: ...`
- Не злоупотребляй — больше двух предупреждений на файл = плохо структурированный файл

## Эмодзи

- В **обычных файлах** — не используем
- В `INDEX.md` — для разделов (опционально)
- В `glossary.md` — для категорий (опционально)
- В заголовках главного `README.md` — допустимо

## Длина абзаца

- 2-4 предложения
- Если абзац разрастается — это нескольких мыслей, которые лучше разделить

## Терминология

**Все термины — только в той форме, как зафиксированы в [glossary.md](glossary.md).** Если хочется использовать новый термин — сначала добавь в глоссарий.

## Дисциплина источника истины

- Бизнес-правило описано **в одном месте**. Везде остальные — ссылки.
- Если факт повторяется в двух файлах — рано или поздно расходятся. Один источник, ссылки.

См. [maintenance.md](maintenance.md), Обязательство 2.
