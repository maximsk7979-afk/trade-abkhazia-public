# Eva — архитектура

> Компоненты, потоки и навыки Евы. Решение — [ADR-013](../../90-decisions/ADR-013-eva-agent-architecture.md). Память детально — [memory-system.md](memory-system.md). Характер и принципы — [vision.md](vision.md).

## Общая схема

```
                 ┌─────────────── Telegram ───────────────┐
   Клиенты ──────┤  (диалоги)                              ├────── Менеджеры
                 └────────────────┬────────────────────────┘   (алерты, дайджесты)
                                  │
                        ┌─────────▼──────────┐
                        │   ЕВА (сервис)     │   Node.js на VPS,
                        │   агентный цикл    │   замещает bot_expeditor
                        │   Claude + tools   │
                        └───┬───────┬────────┘
              ┌─────────────┘       └──────────────┐
     ┌────────▼─────────┐               ┌───────────▼──────────┐
     │  ПАМЯТЬ ЕВЫ       │               │  НАВЫКИ (tools)      │
     │  (Postgres)      │               │  чтение/запись в     │
     │  • переписки (A) │               │  бизнес-систему      │
     │  • память кли-та │               │  через data-API      │
     │    (B)           │               └──────────┬───────────┘
     │  • очередь учёбы │                          │
     └──────────────────┘               ┌───────────▼───────────┐
                                        │  Бизнес-данные (KV→PG) │
                                        │  клиенты, продажи,     │
                                        │  рейсы, расчёты, склад  │
                                        └───────────┬────────────┘
                                                    ▲
                                        ┌───────────┴───────────┐
                                        │  trade_app (UI):      │
                                        │  модуль «CRM /        │
                                        │  Переписки»            │
                                        └───────────────────────┘
```

## Компоненты

### 1. Сервис Евы (рантайм)
Node.js на VPS, замещает `bot_expeditor` (наследует Telegram-токен, ADR-005). Внутри — **агентный цикл**: входящее сообщение → сбор контекста (память) → вызов Claude с набором инструментов → выполнение вызванных инструментов → ответ клиенту → фоновое обновление памяти.

### 2. Канал
Telegram Bot API. Старт — polling; webhook — позже. Поддерживает диалоги с клиентами и алерты/дайджесты менеджерам.

### 3. Мозг
Claude (Sonnet для диалога; путь — Bedrock или прямой Anthropic API, выбор при реализации). Системный промпт собирается из принципов ([vision.md](vision.md)) + общих знаний (слой C) и **кэшируется**; память клиента и хвост диалога добавляются на каждый запрос.

### 4. Память (Postgres)
Четыре слоя — см. [memory-system.md](memory-system.md). Своё хранилище Евы, поднимается отдельно и раньше общей миграции (ADR-013 п. 4).

### 5. Навыки (инструменты)
См. `tools/`. Категории:
- **Чтение бизнес-данных**: профиль клиента, остатки/цены, ближайшие рейсы, баланс/долг, история заказов.
- **Запись**: создать/обновить клиента, создать заявку (ПС/ЗД/ЗР по [ADR-007](../../90-decisions/ADR-007-sales-canonical-model.md)), зафиксировать оплату.
- **Коммуникация**: сообщение клиенту, алерт/дайджест менеджеру.
- **Эскалация**: `escalate_to_manager`.
- **Память**: чтение/запись слоёв A и B.

Бизнес-данные идут через **data-API** (`/api/storage/<key>`), тот же, что у `trade_app`. Фотографии — через отдельный endpoint `/api/photos` ([photo-infrastructure.md](../../40-system/photo-infrastructure.md), [ADR-016](../../90-decisions/ADR-016-photo-infrastructure.md)).

### 6. Фото-модуль (`code/eva/src/photo/`)

Подсистема приёма и обработки фотографий из Telegram. Реализует слои (а), (г) фото-инфраструктуры ([ADR-016](../../90-decisions/ADR-016-photo-infrastructure.md)):

```
code/eva/src/photo/
  raw-photo.js              ← слой (а): скачивание + нормализация в RawPhoto
  album-buffer.js           ← слой (а): буферизация альбомов по media_group_id
  dispatcher.js             ← слой (г): выбор base (активный сценарий → inline-кнопки)
  upload-client.js          ← слой (в): обёртка POST /api/photos
  handlers/
    client-locations.js     ← GAP-018
    shipments.js            ← GAP-020 (с распознаванием накладной)
    skus.js                 ← GAP-021
    purchase-offers.js      ← GAP-022
```

Сессия Евы хранит `activeScenario` и `expectingPhoto = {base, entityId}`: сценарий-владелец фото-ожидания ставит флаг, диспетчер видит и проводит фото без уточняющего диалога. После Ит.4 — в Postgres (`eva_sessions`).

Связи: сценарии (`scenarios/<name>.md`) используют флаг `expectingPhoto`. Например, [client-onboarding](scenarios/client-onboarding.md) шаг 9 ставит `{base: "client-locations", entityId: <создаваемый клиент>}`.

### 7. CRM-слой (проактив)
Планировщик (cron) с правилами: напоминание о рейсе (по ассортименту клиента из слоя B), ре-активация, напоминание о долге, дайджест менеджеру. Эскалация — `escalate_to_manager` из диалога (жалоба, торг сверх полномочий, аномалия, просьба клиента) → алерт менеджеру + ссылка на переписку + возможность перехвата.

### 8. UI для сотрудников
Модуль «📨 CRM / Переписки» в `trade_app`: список клиентов → лента диалога (A) → карточка памяти (B) → перехват + лента напоминаний менеджеру.

## Поток: входящее сообщение клиента

1. Telegram → сервис Евы получает сообщение от клиента X.
2. Записать сообщение в слой A.
3. Собрать контекст: системный промпт (C, кэш) + память клиента X (B) + последние N сообщений (A).
4. Вызвать Claude с инструментами. Claude может вызвать инструменты (узнать баланс, остаток, создать заявку, эскалировать).
5. Сформировать ответ → отправить клиенту → записать в слой A.
6. Фоново: проход обновления памяти клиента (B) — новые факты, обновлённое резюме.

## Поток: проактивное напоминание (CRM)

1. Cron-правило срабатывает (например, «рейс PRJ-001 приходит послезавтра»).
2. Выбрать клиентов, чей ассортимент (B) пересекается с товарами рейса.
3. Сформировать персональное сообщение каждому → отправить → записать в A.

## Поток: эскалация

1. В диалоге Ева вызывает `escalate_to_manager` с причиной и кратким контекстом.
2. Менеджеру (managerId клиента) — алерт в Telegram + ссылка на переписку в CRM-модуле.
3. Менеджер может перехватить диалог; Ева сообщает клиенту о подключении человека.
