## Суть

В этом процессе Ева — **проактивный оркестратор**: не отвечает на входящее, а **сама по
расписанию** (грузинское время, UTC+4) инициирует переписки с разными ролями, ведёт рейс по
этапам, контролирует дедлайны и шлёт алерты. Это качественно новая для Евы способность —
сегодня Ева **реактивна** (только отвечает).

## Роли в переписках (гейтинг по ADR-022)

| Контрагент переписки | Роль | Что Ева делает |
|---|---|---|
| Генеральный директор | `gen_director` | согласование объёма/поставщика (шаг 1), увеличение лимита (5–6), назначение водителя (7) |
| Владелец | `owner` | эскалация при срыве дедлайнов |
| Поставщик | `supplier` (внешн., изолирован) | заказ объёма (2), выписка накладной (8) |
| Закупщик | `buyer` | согласование проезда (9) |
| Клиент | `client` | приём заказов из лимита рейса (4) — через мини-апп |

## Поток (по шагам процесса)

```
D0 15:00 ГД → объём X, поставщик   (нет ответа к 16:00 → эскалация owner)
D0        Ева → поставщик: заказ X на D4 (подтверждение / отказ+причина→ГД)
D0        Ева → рейс PRJ-004 на D4, лимит ≤ X
D0..      клиенты заказывают в мини-аппе из лимита (отсечка 13:00 D4)
          лимит исчерпан → Ева → ГД (инфо) → согласование +Y → Ева поднимает лимит
D3 14:00  ГД → водитель            (нет к 16:00 → эскалация owner)
D3        Ева → поставщик: накладная на X+Y + фото ВУ/техпаспорта водителя
          поставщик → PDF (груз.) → Ева переводит и сверяет (дата, кол-во, цена, ФИО)
D3 ≤18:00 Ева → закупщик: подтвердить согласование проезда (нет к 17:30 → напоминание+owner)
D3веч/D4  погрузка/оплата закупщиком (мини-апп) — отдельные модули
D4        доставка клиентам
```

## Новые возможности Евы, которых сейчас НЕТ (scope реализации)

- **Планировщик (cron)** — триггеры по грузинскому времени (15:00/16:00 D0; 14:00/16:00 D3; 17:30/18:00 D3).
- **Исходящие переписки** — Ева сама инициирует диалог (не ответ на входящее) с ГД/поставщиком/закупщиком/владельцем.
- **Канал Ева ↔ поставщик** — поставщик как контакт бота (роль `supplier`, `tgChatId`), изолированный скоуп.
- **Контроль дедлайнов + алерты** — таймеры по этапам, эскалация при нарушении.
- **Накладная-PDF** — приём, перевод с грузинского, сверка 4 полей (отдельный под-этап; Invoice ADR-010/011).
- **Чтение фото водителя** — ВУ/техпаспорт из карточки контрагента `transport` (поля добавить).
- ~~Лимит ящиков рейса~~ — ✅ `orderCapacity` уже реализован и enforced (`order-service.js`); Еве нужны лишь инструменты задать/изменить (`create_banana_trip`/`set_trip_capacity`).
- ✅ **Ядро-автомат** — [`cycle-machine.js`](../../../../code/eva/src/procurement/cycle-machine.js): чистый `transition()`, состояния/события/эффекты, 46 тестов (готово 2026-06-10).
