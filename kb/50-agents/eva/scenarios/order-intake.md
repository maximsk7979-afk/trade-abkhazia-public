# Сценарий: приём заявки под рейс

> **Техническая сторона Евы/мини-аппа** для приёма заявки. Бизнес-взгляд (что происходит, поля, правила) — в процессе роли [sales-manager/processes/order-intake.md](../../../30-roles/to-be/sales-manager/processes/order-intake.md). Поверхность — [ADR-019](../../../90-decisions/ADR-019-eva-mini-app.md); модель заявки/цены — [ADR-020](../../../90-decisions/ADR-020-order-intake-banana-pricing.md); типы — [ADR-007](../../../90-decisions/ADR-007-sales-canonical-model.md).
>
> Статус: **реализован и развёрнут**. Банан FP (по ящикам, 2026-06-04) + **весовые позиции** (помидоры/огурцы, по упаковкам, GAP-036, 2026-06-06) + **корзина** (GAP-035).
>
> ⚠️ **Обновлено [ADR-021](../../../90-decisions/ADR-021-daily-mixed-trips-day-order.md) (2026-06-06):** ежедневные **смешанные** рейсы. Клиент выбирает **день доставки** (4 кнопки: завтра/+2/+3/+4), а не рейс из списка; ассортимент — **единый каталог по проектам клиента** (секции Овощи→Фрукты→Бананы→Прочее), **смешанная корзина** (банан + овощи в одной заявке). Рейс — ленивое авто-создание на дату, отсечка D−1 20:00 МСК, **без лимита вместимости**. Эндпоинты `/order-days`, `/day-catalog`, `/order {date,delivery,lines}`. Разделы ниже про «витрину рейсов» и раздельные потоки — историческая часть (механика цены/заморозки/изоляции в силе).

## Суть

Структурная операция (заказ) идёт **в мини-аппе**, а не диалогом — чтобы исключить ошибки распознавания свободного текста ([ADR-019](../../../90-decisions/ADR-019-eva-mini-app.md)). Ева в чате: **подтверждает** заявку, **уведомляет**, **эскалирует** нестандарт, ведёт общение. Цена и остаток вместимости считаются **на сервере**.

## Шаги (со стороны системы)

### 1. Открытие и идентификация
Мини-апп открывается menu-кнопкой или inline-кнопкой Евы. `trade-api` **валидирует `initData`** (HMAC по токену бота) и резолвит роль (`resolveIdentity`: staff → owner/manager, client → client). Клиентский скоуп зашит на сервере (GAP-030).

### 2. Витрина рейсов
Сервер отдаёт **открытые рейсы** (время не вышло **и** `остаток = вместимость − сумма заказов > 0`), отсортированные по дате доставки, с **остатком мест**. Менеджеру — выбор **своего** клиента.

### 3. Расчёт цены (live)
При изменении количества/способа получения — сервер считает цену по **банановому правилу** ([ADR-020](../../../90-decisions/ADR-020-order-intake-banana-pricing.md) Часть 2), модель **«якорь + надбавки»**:
- цена ступени = `якорь + надбавка`; цена по **объёму**, не по сегменту;
- **+100/коробка** при доставке; **фикс-цена клиента** перебивает (всё включено), но **не ниже якоря** (пол);
- подсказка-апсейл («ещё N ящиков → X/коробка»).

**Цена в чат (без приложения):** на вопрос клиента «почём банан» Ева через `get_my_prices` отвечает **прямо в чат** — фикс-цену клиента или действующую сетку (самовывоз — без доставки, доставка — с +100). В приложение направляет только для **оформления** заказа.

**Инструменты прайса (staff):**
- `manage_banana_pricing` — владелец меняет **якорь**; владелец+ГД — надбавки/ступени/розницу/доставку.
- `set_client_banana_price` — привязка клиента **сетка/фикс-цена** (фикс ≥ якоря): **менеджер — только своим клиентам** (инструмент проверяет `managerId`), **ГД/владелец — любым**.
- При смене якоря — **каскад**: Ева пишет каждому менеджеру и пошагово переназначает фикс-цены его клиентов *(Фаза 2)*.

### 4. Отправка (атомарно)
Сервер под блокировкой: проверяет **остаток вместимости**, оформляет **сколько влезает** (если просили больше — частично + сообщает остаток), создаёт/обновляет **ЗР** (`order-trip`, привязка `tripId`), статус **«Новая»**, **замораживает цену** в строке. Гонки исключаются серверной атомарной проверкой лимита.

### 5. Подтверждение и уведомления
Ева подтверждает клиенту **в чате** (не только в аппе), уведомляет **менеджера** клиента и **владельца** ([ADR-020](../../../90-decisions/ADR-020-order-intake-banana-pricing.md) Часть 3).

### 6. Редактирование / отмена (до отсечки)
Одна заявка на клиента на рейс. Пока рейс открыт — изменить количество (пересчёт цены, возврат ящиков в остаток при уменьшении) или **отменить**. После отсечки — заблокировано.

## Весовой вариант (помидоры/огурцы) — GAP-036

Те же шаги, отличия:
- **Витрина рейсов** — `GET /trips?kind=weighted`: не-банановые рейсы с `orderCutoffAt` в будущем, **без лимита вместимости** (лимит в кг — GAP-035).
- **Выбор позиции** — `GET /weighted-skus?tripId=&group=`: товар · упаковка · нетто-вес (`gw−tw`) · ₽/кг. Заказной = цена/кг задана владельцем, SKU активен, проект подходит рейсу.
- **Расчёт цены** — `GET /price?kind=weighted&skuId=&qty=` (qty = **упаковок**): `estKg = qty × нетто`, `estTotal = estKg × ₽/кг` (+ надбавка/кг при доставке; фикс-цена/кг клиента перебивает). Сумма **ориентировочная** — Ева/мини-апп всегда помечают: точная после взвешивания при отгрузке.
- **Отправка** — `POST /order { kind:"weighted", tripId, skuId, qty, delivery }`: ЗР с `miniOrder.kind="weighted"` (заморожены `estTotal`, `unitPrice`=₽/кг, `estKg`), статус «Новая». Лимит вместимости не проверяется.
- **Цену/кг задаёт владелец** через Еву — инструмент `manage_weighted_pricing` (owner-only): `view` показывает все весовые SKU и текущие цены; `update` принимает `prices:[{skuId,pricePerKg}]`, `remove`, `deliverySurchargePerKg`. Позиция доступна клиенту, только когда у её SKU задана цена.
- **Корзина (GAP-035, 2026-06-06):** заявка может содержать **несколько весовых позиций** под один рейс (`POST /order {kind:"weighted", lines:[{skuId,qty}]}`); `miniOrder` v2 со строками. Банан — отдельный одиночный поток.

## Краевые случаи

| Ситуация | Поведение |
|---|---|
| Запросили больше остатка вместимости | Оформляем **сколько влезает** + «на этот рейс осталось N ящиков» |
| Рейс закрылся (время/лимит) во время оформления | Submit отклоняется: «приём на этот рейс закрыт», предложить другой открытый рейс |
| Две заявки гонкой у предела вместимости | Серверная атомарная проверка лимита — пробить машину нельзя |
| Клиент уменьшил/отменил заявку | Ящики возвращаются в общий остаток рейса |
| Изменение прайса после оформления | На заявку **не влияет** (цена заморожена); при скачке — менеджер пересматривает вручную |
| Менеджер оформляет за **чужого** клиента | Не показываем чужих клиентов (скоуп `managerId`) |
| Незнакомец (нет в staff/clients по `initData`) | Доступа в апп нет; в чате — эскалация/онбординг, заказ не оформляется |
| Клиент без Telegram | Мини-аппа нет; заявку оформляет **менеджер** за него |
| Торг / запрос скидки / нестандарт | `escalate_to_manager` — оформляет/решает человек |

## Инструменты / эндпоинты (проектируются)

**`trade-api` (мини-апп):**
- `verifyInitData` (мидлвара, HMAC) + `resolveIdentity` (порт из рантайма Евы)
- `GET /api/mini/trips` — открытые рейсы + остаток мест (скоуп по роли)
- `GET /api/mini/price?qty=&delivery=&clientId=` — цена по объёму (банановое правило)
- `POST /api/mini/order` — создать/изменить ЗР (атомарная проверка лимита, заморозка цены)
- `DELETE /api/mini/order/:id` — отмена до отсечки
- `GET /api/mini/balance`, `GET /api/mini/history`, `GET /api/mini/shipment/:id` — баланс/история/детализация (только своё)

**Ева (рантайм):**
- web_app-кнопки (menu + inline), подтверждение в чате
- `notify_manager`, `notify_owner`, `escalate_to_manager`
- owner-управление банановым прайсом (set base/tiers) — см. [ADR-020](../../../90-decisions/ADR-020-order-intake-banana-pricing.md) Часть 2.4

## Что нужно в коде (для реализации)

1. **Мини-апп фронт** (отдельный лёгкий, мобильный) — экраны заказа/баланса/истории, ролевой рендер.
2. **Валидация `initData`** + резолв личности на сервере (критический путь GAP-030).
3. **Банановый прайс**: признак `pricingMode=volume-tier` у товара; хранилище сетки (таблица цен), управляемое через Еву (owner); функция `priceForBanana(qty, delivery, client)`.
4. **Рейс**: поля `cutoffTime`, `capacity`; расчёт `остатка = capacity − sum(заявки)`; атомарная проверка на submit.
5. **Заявка ЗР**: создание/редактирование/отмена до отсечки; заморозка цены в строке.
6. **Уведомления** менеджеру/владельцу; подтверждение в чате.
7. **Баланс/история** (только своё): долг/сальдо, лента заявок/отгрузок + оплаты, детализация отгрузки. (**Лимит долга — отложен**, [GAP-033](../../../00-meta/gaps.md#gap-033).)

## Открытые вопросы / отложено

- **Лимит долга** клиента — отображение и действие при превышении ([GAP-033](../../../00-meta/gaps.md#gap-033)).
- **Нехватка на рейсе** (привезли меньше/брак) — аллокация ([GAP-031](../../../00-meta/gaps.md#gap-031)); **возврат/брак** на доставке ([GAP-032](../../../00-meta/gaps.md#gap-032)). Уровень — отгрузка (экспедитор).
- **Кодификация прайса**: переход от ручной сетки к авто-правилам на базовой цене Краснодара ([GAP-034](../../../00-meta/gaps.md#gap-034)).
- **Заказ из наличия** в клиентском аппе — после MVP (сейчас только под рейс).
- Расписание рейсов как **константа** с автогенерацией — после выхода на регулярную работу.
