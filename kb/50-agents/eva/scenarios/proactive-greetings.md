# Сценарий: проактивные поздравления

> Проактивная инициатива Евы ([vision.md](../vision.md) п. 5 «Инициатива»). Решено 2026-05-31. Часть CRM-слоя ([architecture.md](../architecture.md) §7), родственно напоминаниям. Статус — `design`.

## Идея

Ева сама поздравляет клиента в значимые дни **персональным** поздравлением — клиент чувствует, что о нём помнят, это сближает. Поздравление **не шаблонное**: Ева анализирует слой A (историю переписки), находит тёплые детали и формирует личное пожелание.

## Два источника поводов

**1. Личные даты** — из `important_dates` (слой B, блок 1): ДР клиента и родственников, другие значимые даты. Хранятся **структурно**, чтобы шедулер мог сработать.

**2. Календарные праздники (для всех клиентов):**
| Дата | Кого |
|---|---|
| 1 января — Новый год | всех |
| 7 января — Рождество Христово | всех |
| 23 февраля | мужчин |
| 8 марта | женщин |

Поздравление и на календарный праздник остаётся персональным (Ева добавляет тёплую деталь из истории).

## Механика

```
Ежедневный cron:
  1. Кто сегодня именинник (клиент/родственник из important_dates)?
     + какой сегодня календарный праздник (и кому он применим по полу)?
  2. Для каждого получателя — анализ слоя A → персональное поздравление.
  3. Отправка утром.
```

## Правила

- Слать **утром**, **один раз** в дату.
- Для родственника — поздравить уместно («передай супруге…» / поздравить клиента с ДР близкого).
- В дни массовых праздников — **раскидать отправку по времени** (не в одну секунду на всех).
- **Пол клиента** нужен для 23.02/8.03: определять автоматически (по имени/общению), при неуверенности — уточнить на [знакомстве](client-introduction.md). См. [GAP-028](../../../00-meta/gaps.md#gap-028).

## К реализации

- Структурное поле `important_dates` в B + ввод дат (Ева на знакомстве/в общении, или менеджер в карточке).
- Ежедневный шедулер (cron) + генерация поздравления из A.
- GAP: [GAP-028](../../../00-meta/gaps.md#gap-028).
