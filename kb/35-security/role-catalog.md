# Каталог ролей

Единый словарь ролей системы Trade Abkhazia. Источник истины ролей сотрудников — массив `roles`
в справочнике `trade-cat-staff`. Решение и механика — [ADR-022](../90-decisions/ADR-022-role-model-rbac.md).
Детальные права — [role-permissions.md](role-permissions.md).

> Один человек может иметь несколько ролей; одну роль — несколько человек. Роли назначаются
> через систему. Назначения ниже сверены с боевым KV на 2026-06-09 — при изменениях обновлять.

> **Канонический словарь ролей — массив `STAFF_ROLES`** в `trade_app_v3.jsx` (11 ролей), он же в
> форме «Добавить сотрудника»: `owner`, `gen_director`, `fin_director`, `ops_manager`, `expeditor`,
> `sales_manager`, `warehouse`, `buyer`, `accountant`, `loader`, `driver`. Таблица ниже синхронизирована
> с ним 2026-06-19 (ранее не хватало `expeditor`/`accountant`/`loader`/`driver`). **Не плодить роли
> вне этого словаря.**

## Внешние роли

| Роль | Кто | Зона / скоуп | Поверхности |
|---|---|---|---|
| `client` | Клиенты (`trade-cat-clients`, опознаются по `tgChatId`) | Только свои данные: баланс, заказы, цены; оформление заявки. Жёсткая фильтрация по `clientId` | Ева, мини-апп |
| `supplier` ❗новая | Рамаз (П-005), Уча (завести). В `trade-cat-suppliers`, опознаются по новому полю `tgChatId` | **Только закупочная переписка с Евой.** Ни одного инструмента данных. Не видит цены, балансы, других поставщиков, клиентов | Ева (изолированно) |
| `demo` (2026-07-07, [GAP-078](../00-meta/gaps.md#gap-078)) | Один общий логин `demo` (инвесторы/показы); пароль меняет `owner` после показов | **Только чтение веб-TradeApp** — живые данные как есть (решение владельца 2026-07-06), включая отчёты P&L/Касса/Товарооборот/Балансы. Любая запись → 403 fail-closed на сервере. НЕ staff-роль (нет в `STAFF_ROLES`/`trade-cat-staff`) — внешняя, изолированная как client/supplier; существует только в сессии веб-входа ([auth-architecture.md](auth-architecture.md)) | trade_app (веб) |

## Уточнение по водителю (обновлено 2026-06-19)

**Водитель — это роль `driver`** (есть в `STAFF_ROLES`), а не «не-роль». Прежняя формулировка
«водитель = только контрагент, с системой не взаимодействует» **устарела**: в рамках финблока
водитель **держит подотчётный нал, делает обмен ₽→₾ и вносит денежные события через Еву** — это
требует роли. Контрагенты категории `transport` (КА-007 Джамна, КА-008 Тэриэл, КА-009 Алико в
`trade-cat-contragents`) остаются **стороной-получателем при оплате транспортных услуг** (статья
расхода `transport`). Классификацию конкретного водителя (staff с ролью `driver` ↔ контрагент)
ещё предстоит подтвердить. Ева читает из карточки контрагента фото (ВУ, техпаспорт — поля добавить);
совмещение закупки на рейсе → дополнительно роль `buyer`.

## Статус реализации (на 2026-06-09)

- ✅ **Резолв возвращает полный массив ролей** — Ева (`message-log.resolveIdentity`) и мини-апп
  (`mini-auth.resolveIdentity`) теперь отдают `{ roles:[...], staffId, clientId, … }`;
  грубый класс (`owner/manager/client/supplier`) сохранён для совместимости. Задеплоено.
- ✅ **Гейтинг по ролям** — Ева: RBAC-ядро `src/tools/access.js` (`roleAllowed`), `tool.access`
  поддерживает список ролей + `staff/client/any/supplier`, `owner`-суперюзер, fail-closed;
  покрыто тестом `test/tools-access.test.js` (21 проверка). Задеплоено.
- ✅ **Роль `supplier` (плумбинг)** — резолв узнаёт поставщика по `tgChatId`, отдельный
  изолированный системный промпт, без инструментов данных. Задеплоено.
- ⏳ **Данные:** ни у одного поставщика ещё не задан `tgChatId` (роль `supplier` дормантна,
  пока Рамаз/Уча не подключены к боту).
- ❌ В карточках контрагентов-перевозчиков нет полей под фото ВУ/техпаспорта (предстоит).
- ⏳ **Гранулярный гейт эндпоинтов мини-аппа** по ролям — резолв готов (`req.mini.roles`),
  сами эндпоинты пока гейтятся грубым классом; тонкая настройка — при модулях закупщика.
