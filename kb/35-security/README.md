# 35-security — Безопасность и права доступа

Протокол безопасности по доступу к данным системы. Матрица прав, политика доступа, классификация данных.

## Содержимое

- [role-catalog.md](role-catalog.md) — **каталог ролей и назначения** (сверено с KV)
- [role-permissions.md](role-permissions.md) — **матрица «роль × функция × право»** (живая, наполняется инкрементально)
- Решение и механика RBAC — [ADR-022](../90-decisions/ADR-022-role-model-rbac.md)

## Ещё предстоит (заглушки)

- **access-policy.md** — общая политика доступа к системе и данным
- **data-classification.md** — классификация данных (публичное / внутреннее / конфиденциальное)
- **auth-architecture.md** — реализация аутентификации (JWT, сессии)
- **infrastructure-access.md** — доступ к VPS, БД, репозиторию, токенам
- **audit-logging.md** — что логируется, как смотреть

## Текущее состояние

- В коде системы **авторизации нет**: API без auth, CORS `*`. Это блокер для запуска Евы с реальными ролями.
- Задача "Реализовать ролевой доступ (RBAC)" — в [roadmap](../65-roadmap/current.md).

## Принципы

1. **Posterior данные** (продажи, выручка, P&L) — доступ только Максиму, бухгалтеру, оп-менеджеру (с ограничениями).
2. **Закупочные цены** — не показываются клиентам и менеджерам продаж.
3. **Чужие продажи** — менеджер продаж видит только свои.
4. **Контрагенты-партнёры** (Лия) — видят только свои операции.

Детальная матрица — будет в `role-permissions.md`.
