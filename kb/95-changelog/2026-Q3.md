# Changelog — 2026 Q3

## 2026-07-01 — Аудит и синхронизация раздела «Касса» (единое ядро + бэкфилл вторых ног)

**Запрос владельца:** проверить «Кассу» — единый ли калькулятор, синхронны ли интерфейсы, нет ли дублей/хвостов/разъехавшихся полей.

**Аудит (данные + код):** структурно чисто — нет дублей id, битых/безногих движений, сирот-кошельков, рассинхрона валют. Найдено: (1) браузерная «Касса» считала остаток своей копией формулы (`trade_app_calc.cashBalances`), отдельной от `cash-service` — численно совпадала, но дубль (дрейф по ADR-025); (2) `recordCashInflow` не идемпотентна (`id='ДД-'+Date.now()`); (3) 1 **сирота** — нога `ДД-1782059378374` (10 000 ₽) на удалённый settlement `S-1782059485871`; (4) **824 724 ₽** клиентских оплат (68 из 132) без второй (кассовой) ноги (фича с ~20.06 + сотрудники без ₽-кошелька) — незавершённость Ф-2.

**Сделано:**
1. **Единое ядро `cash-core.cjs`** (как `trip-cost-core`): остаток кошелька считается в одном месте; `cash-service.js` и фронтовый `trade_app_calc.cashBalances` — делегаты. Паритет с прод-данными ✓, цифры не изменились. Деплой: ядро в `/var/www/trade/` и `frontend/src/trade-api/`, фронт-бандл `index-BR6bxMNe.js`.
2. **Идемпотентность `recordCashInflow`**: при наличии `refId` переиспользуется id существующей ноги (как браузерный `payCashLeg`) → ретрай/повтор не плодит дубль. Деплой trade-api (pm2).
3. **Синхронизация касса↔расчёты** (миграция `backfill-cash-legs.js`, бэкап `/var/www/_bak/2026-07-01-cash-backfill/`, DRY→боевой, идемпотентна): удалена 1 сирота; заведены **68 недостающих вторых ног в кассу Ивана Голованова (КС-003)** — 65 приходов (818 274 ₽) + 3 возврата брака (6 450 ₽), дата/сумма = ровно как в settlement (решение владельца). Итог: сирот **0**, settlements клиентов без ноги **0** — полный синхрон. КС-003: 263 178 → **1 065 002 ₽**.

**Инварианты (проверено на бою):** кассовые движения — отдельная проекция, `balance-service`/KPI/товарооборот их не читают → **балансы клиентов = 190 468,9 НЕ изменились**; дублей `refId` нет; Ева и мини-апп читают кассу через канон `cash-service`. Осталось на Ф-2: кассовые `outflow` для расходов/оплат поставщикам, строгая валидация `validateDoc`, дедуп полей `name`/`desc`.

## 2026-07-01 — Фикс KPI «Продажи»: долг сведён с «Расчётами» (единый калькулятор)

**Симптом (аудит по двум снимкам владельца):** вкладка «Продажи» показывала долг **636 607,9 ₽**, вкладка «Расчёты → Клиенты» — **190 468,9 ₽**. Расхождение **446 139,0 ₽**.

**Аудит на боевых данных (свёл до рубля):** правильное число — **190 468,9** (канон `balance-service`, GAP-058). KPI-карточки «Продажи» (Выручка/Оплачено/Долг) — отдельный расчёт, разошедшийся с каноном (дрейф ADR-025). Две причины:
1. **394 955,0 ₽** — «Оплачено» считалось только по журналу `settlements` и НЕ включало `saleData.paid`. Оплаты разовых (`__walk_in__`) лежат именно там (settlement для walk-in не создаётся) → разовые выглядели неоплаченными.
2. **51 184,0 ₽** — в «Выручку» попадали **отменённые** продажи (5 шт: ПС-038/039/091/116/122), которые `balance-service` исключает.
394 955,0 + 51 184,0 = 446 139,0 (точно).

**Фикс** (`trade_app_v3.jsx`, SalesMod, KPI-блок): (а) отменённые исключены из выручки; (б) «Оплачено» = `salePaid` продажи (`saleData.paid` у sale-direct / `shipmentPaid` у заявок) + платежи/возмещения из `settlements` — как в `balance-service`. Проверка на боевых данных: Выручка 2 295 101,9 − Оплачено 2 104 633,0 = **Долг 190 468,9** = «Расчёты» ✓. Только отображение — продовые данные не менялись.

**Аудит Евы и мини-аппа (по запросу владельца):** подтверждено — баланс/долг везде через единый `balance-service` (Ева по HTTP `/api/client/:id/summary`; мини-апп `clientBalance`/`clientsRoster`; админка «Расчёты» — тоже). **Двойного учёта оплат нет**: walk-in → только `saleData.paid`, именованный → только settlement; поля не пересекаются, откат оплат синхронизирован. Единственный неканон — этот KPI «Продажи» — устранён.

**Деплой:** trade-app (бандл `index-CNVRwDAo.js`). Бэкенд/данные не тронуты. Без GAP (решение владельца — правим сразу).
