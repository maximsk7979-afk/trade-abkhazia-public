# Продажа со склада в мини-приложении

> Спецификация согласована с Максимом 2026-06-21 (пошаговое обсуждение). Цель — дать менеджеру
> в мини-аппе продажу **со склада минуя доставку**, собрать все продажи под единой вкладкой
> «Продажа», ввести единый протокол клиентских сообщений и живой расчёт.
> Сценарий — **самовывоз / отпуск со склада** (товар физически на складе, списываем сразу).
> Переиспользуем готовый `sale-direct-service` (ADR-025, без дубля доменной логики).

## Контекст (что было до)

- «Продажа из доставки» в мини-аппе = вкладка «Доставка» (поток: формирование машины →
  погрузка FIFO → отгрузка по точкам → завершение). Внутри уже была «допродажа с машины».
- «Продажа со склада» (sale-direct, `ПС-`) существовала **только в браузер-админке**
  (`POST /api/v2/sale-direct/save|cancel`, `requireInternalToken`) — мини-аппу недоступна.
- Чат Евы продажи не оформляет и **не должен** (ADR-013/ADR-020): структурные операции идут
  в мини-апп; Ева подтверждает/уведомляет/эскалирует. Эта работа — в **мини-аппе**, не в чат-tools.

## Функциональная спецификация

### 1. Вкладка «Продажа» (бывшая «Доставка»)
Два раздела: **«Со склада»** (новый) и **«Доставка»** (существующий поток целиком).
Если роли доступен один раздел — открывается сразу, без переключателя из одного пункта.

### 2. Позиции (экран как отгрузка, «Вариант C»)
Интерфейс **идентичен экрану отгрузки** по наполнению/функционалу:
- товар выбирается из списка, где **только то, что есть на складе** (`qtyRem` > 0); карточка
  с полями появляется после выбора (не вываливаем весь склад);
- тарный — кол-во + цена ₽/ед; весовой — **этапное взвешивание** ({тары, брутто кг}, «+ ещё
  взвешивание», удаление подхода), авто-нетто = брутто − тары×tw, цена ₽/кг нетто;
- остаток виден в карточке;
- **цена — ручной ввод** (автоподстановка из прайса отложена до модуля «Прайс-лист»);
- нехватка остатка — **мягкое предупреждение** (продать можно, минус возможен → инвентаризация),
  в отличие от доставки (там жёсткий блок по объёму машины).

### 3. Клиент и оплата
- **Выбор клиента: все роли видят всех клиентов** (ограничение «только свои» снято везде —
  склад, отгрузка, продажа с машины, приём оплаты). Можно постоянного или разового.
- Разовый — дефолт оплаты = сумма отгрузки, **оплата обязательна** (в долг нельзя).
- Постоянный — поле «Оплата ₽» пустое + справочные строки «Сумма текущей отгрузки…» и
  «Общая сумма долга…» (старый долг + текущая отгрузка). Непокрытый остаток → долг.
- Оплата → вторая нога в **₽-кошелёк проводящего** (касса), как при приёме оплаты клиента.

### 4. Атрибуция
Касса (оплата) и `byStaffId` продажи — **проводящему**; `managerId` клиента не трогаем
(закрепление за своим менеджером сохраняется). Склад списания = офис проводящего
(сейчас один — О-001 Сухуми; нет officeId → О-001).

### 5. Живой расчёт — во ВСЕХ формах мини-аппа
Суммы (стоимость позиции, сумма отгрузки, баланс после) считаются **в момент набора**,
без потери фокуса/курсора (точечное обновление цифр, не полная перерисовка экрана).

### 6. Единый протокол уведомлений (для всех продаж: склад + доставка + приём оплаты)
- **Внутренние:** проводящему — подтверждение + его касса; владельцу + ops_manager — то же
  + имя проводящего.
- **Клиенту** (постоянный, зарегистрирован в Telegram) — **раздельные обязательные**:
  отгрузка → сообщение + PDF-накладная (про оплату не пишем); факт оплаты (Y>0) → отдельное
  сообщение об оплате; отмена → цепочка сообщений об отмене (отгрузки и оплаты).
- Механизм — общий хелпер, дёргается из всех точек продажи (без дубля).

### 7. Отмена (правки нет — только отмена + завести заново)
- **Со склада:** только свою и только в тот же день (позже — владелец в браузере). Сторно:
  товар → на склад, снятие начисления/оплаты клиента, **откат кассовой ноги** + цепочка уведомлений.
- **С доставки (новое):** отмена **одной отгрузки** клиенту, пока доставка не завершена (после —
  владелец). Товар возвращается **обратно в доставку** (на машину, не на склад); FIFO склада
  не трогаем. Откат оплаты/долга/кассы + цепочка уведомлений. Закрывает forward-note из C2.4b.

### 8. Владение доставкой
Доставка привязана к создателю (`ownerStaffId`); рядовой исполнитель видит/оперирует
**только своей** активной доставкой. **owner / ГД / ops_manager** видят все и могут оперировать любой.

### 9. «Продажа с машины» (бывшая «Допродажа с машины»)
Переименование; список позиций — только то, что в машине (`free` > 0).

### 10. Экран «Балансы клиентов / оплата»
Все покупатели; **сортировка по долгу** (должники сверху, по убыванию); **строка поиска** по имени.

## Роли и доступ (Обязательство 7 / ADR-022, fail-closed)

Роли только из [role-catalog](../35-security/role-catalog.md) / `STAFF_ROLES`.

| Поверхность | Кто инициирует/исполняет | Кто видит | Гейт |
|---|---|---|---|
| **Продажа со склада** | owner · gen_director · ops_manager · expeditor · sales_manager · **warehouse** | проводящий + (уведомл.) owner+ops | `requireMini` + `requireSaleDirect` (новый) |
| **Раздел «Со склада»** | те же | те же | тот же |
| **Раздел «Доставка»** (формирование/развоз) | owner · gen_director · ops_manager · expeditor · **sales_manager** | своя — исполнитель; все — owner/ГД/ops | `requireMini` + `requireExpeditor` (sales_manager добавляется) |
| **Отмена продажи со склада** | проводящий (своя, сегодня); далее owner/ГД | — | `requireSaleDirect` + проверка byStaffId+дата |
| **Отмена отгрузки с доставки** | исполнитель доставки (пока не завершена); далее owner/ГД | — | `requireExpeditor` + проверка владения |
| **Выбор клиента (везде)** | все продающие роли — все клиенты | — | снят скоуп `managerId` |

- **Кладовщик (warehouse)** получает первую инструментальную поверхность в мини-аппе (раньше 0).
- **sales_manager** теперь видит и раздел «Доставка» (может заводить доставки).
- Чат Евы — **без изменений** (Обязательство 6: продажи в чате не появляются; мини-апп = интерфейс).

## Техническая реализация (ADR-025 — без дубля)

- `POST /api/mini/sale-direct/save` + `/cancel` под `requireMini` + `requireSaleDirect`; внутри —
  тот же `buildSaleDirect`/`buildSaleDirectCancel` без изменений. `byStaffId`/`managerId` из сессии.
- Кассовая нога → общий хелпер `recordCashInflow` (вынести из `/clients/op`, переиспользовать).
- Рассылка клиенту (отгрузка+накладная / оплата / отмена) → общий хелпер; дёргается из
  `sale-direct`, `dlv/ship`, `clients/op`.
- `GET /api/mini/stock?officeId=` — остаток склада (`qtyRem`) по товару/SKU.
- Доставка: поле `ownerStaffId` + фильтрация `dlv/board`/`dlv/points` (кроме owner/ГД/ops);
  новый эндпоинт отмены отгрузки со «сторно-в-доставку».
- Фронт `code/mini-app/app.js`: вкладка «Продажа», экран «Со склада», переименование «Продажа с
  машины», отмена + «Мои продажи сегодня», живой расчёт (`oninput` + точечное обновление сумм),
  балансы (сортировка+поиск), выбор клиента (все).
