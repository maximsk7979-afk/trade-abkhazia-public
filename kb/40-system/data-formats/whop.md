# WhOp — JSON-формат складской операции

## Storage

- Ключ: `trade-whops-v1`
- JS-константа: `SK_WH`
- Содержимое: массив объектов

## Назначение

Записи в журнале склада, фиксирующие каждое движение товара. WhOp — **второй слой учёта остатков**, дополняющий [FIFO-партии](batch.md):

- Партии (batch) считают то, что пришло **через рейс**
- WhOp фиксирует фактические движения и начальные остатки

```
Остаток = FIFO qtyRem + InitialNet − Shipments − Writeoffs + Returns
```

## Типы операций (`opType`)

| `opType` | Описание |
|---|---|
| `initial` | **Начальный остаток**. Используется **одноразово** при старте системы (или нового склада/офиса) — фиксация физического остатка, который уже лежит на складе и не имеет привязки к рейсу. Содержит свою себестоимость (`costPerUnit`) и `unitLabel`. После старта работы новые initial-операции не создаются. |
| `shipment` | Отгрузка клиенту (со склада или через доставку) |
| `writeoff` | Списание (брак, порча) |
| `return` | Возврат с доставки на склад |
| `income` | Приход (планируется для закупки вне рейса — [GAP-009](../../00-meta/gaps.md)) |

## Формат

```json
{
  "id": "WH-...",
  "opType": "initial | shipment | writeoff | return | income",
  "date": "YYYY-MM-DD",
  "prodId": "Т-XXX",
  "skuId": "SKU-XXX-XX",
  "qty": "число строкой (в единицах SKU)",
  "wBrutto": "число строкой (для весовых)",
  "clientId": "К-XXX (для shipment)",
  "deliveryId": "Д-XXX (для shipment через доставку)",
  "desc": "комментарий",
  "officeId": "О-XXX",
  "costPerUnit": "число (для initial)",
  "unitLabel": "₽/кг или ₽/ящ. (для initial)"
}
```

### Поля

| Поле | Тип | Когда | Описание |
|---|---|---|---|
| `id` | string | всегда | ID. Форматы: `WH-XXXX` (общий), `WH-SD-<saleId>-<lineIdx>` (для отгрузки через ПС), `WH-DL-<dlvId>-...` (для доставки) |
| `opType` | string | всегда | См. таблицу выше |
| `date` | string | всегда | `YYYY-MM-DD` |
| `prodId`, `skuId` | string | всегда | Что |
| `qty` | string | всегда | Количество в **единицах SKU** (ящики/мешки/коробки) |
| `wBrutto` | string | для весовых | Брутто-вес позиции (для отчётности) |
| `clientId` | string | для `shipment` | Кому отгрузили |
| `deliveryId` | string | для `shipment` через доставку | В составе какой доставки |
| `desc` | string | необязательно | Свободный комментарий |
| `officeId` | string | всегда | Какой склад |
| `costPerUnit` | number | для `initial` | Себестоимость единицы (для расчёта остатка) |
| `unitLabel` | string | для `initial` | `₽/кг` для весовых, `₽/ящ.` для тарных |

## Примеры

### Начальный остаток (initial)
```json
{
  "id": "WH-INIT-001",
  "opType": "initial",
  "date": "2026-04-28",
  "prodId": "Т-001",
  "skuId": "SKU-001-02",
  "qty": "20",
  "wBrutto": "280.0",
  "officeId": "О-001",
  "costPerUnit": 150,
  "unitLabel": "₽/кг"
}
```

### Отгрузка клиенту (shipment)
```json
{
  "id": "WH-SD-ПС-001-0",
  "opType": "shipment",
  "date": "2026-04-28",
  "prodId": "Т-001",
  "skuId": "SKU-001-02",
  "qty": "5",
  "wBrutto": "32.5",
  "clientId": "К-007",
  "officeId": "О-001"
}
```

### Списание (writeoff)
```json
{
  "id": "WH-WO-001",
  "opType": "writeoff",
  "date": "2026-04-28",
  "prodId": "Т-002",
  "skuId": "SKU-002-01",
  "qty": "3",
  "desc": "Помятая упаковка",
  "officeId": "О-001"
}
```

⚠️ В коде сейчас стоимость списания не сохраняется — см. [GAP-012](../../00-meta/gaps.md).

## Атомарность

Записи `WhOp` создаются автоматически при операциях с продажами/доставками или вручную через UI Склада. Каждая запись — отдельный объект в массиве, **не редактируется** после создания (исключение — финальные правки до завершения доставки).
