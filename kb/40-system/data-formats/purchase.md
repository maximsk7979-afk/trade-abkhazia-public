# Purchase — JSON-формат закупки вне рейса в `app_storage`

> Архитектура: см. [ADR-009](../../90-decisions/ADR-009-multitenancy-projects.md) (Шаг 1) и [GAP-009](../../00-meta/gaps.md).
> Сущность реализована 2026-05-21 (Слой Б Шага 1).

## Назначение

`Purchase` — **закупка вне рейса**: приход товара от местных (абхазских) или
российских поставщиков, минуя грузинский рейс. Нужна для проектов PRJ-002
«Местные овощи» и подобных, где товар берётся локально без курса GEL и без
долей расходов рейса.

Отличия от `Trip` (рейс):
- нет `rate` (курс GEL/1000₽) — суммы сразу в валюте закупки;
- нет `partners[]` / `ourWeight` / долей `expShare`;
- **запись = приёмка**: при сохранении сразу создаются партии FIFO (нет
  отдельного шага «На складе»);
- расходы — одно поле `deliveryCost` (стоимость доставки), а не массив `expenses[]`.

## Storage

- Ключ: `trade-purchases-v1` (константа `SK_PUR`).
- Значение: массив объектов `Purchase`.
- ID: `ЗК-NNN` (Закупка), авто-инкремент, `nextPurchaseId`.

## Структура

```json
{
  "id": "ЗК-001",
  "date": "2026-05-21",
  "status": "На складе",
  "officeId": "О-001",
  "projectId": "PRJ-002",
  "deliveryCost": "1500",
  "items": [
    { "supId": "П-00X", "prodId": "Т-001", "skuId": "SKU-001-02",
      "qty": "20", "price": "55", "pu": "кг", "fw": "", "tc": "" }
  ],
  "supplierPayments": [
    { "supId": "П-00X", "amount": "10000", "paidBy": "Мы" }
  ],
  "cm": "",
  "history": [ { "from": "—", "to": "На складе", "at": "2026-05-21 19:40:00" } ]
}
```

| Поле | Назначение |
|---|---|
| `id` | `ЗК-NNN` |
| `date` | Дата закупки (= дата приёмки на склад) |
| `status` | Всегда `"На складе"` (запись = приёмка; статусной машины нет) |
| `officeId` | Склад прихода |
| `projectId` | Проект (ADR-009). Валюта берётся из `project.defaultCurrency` |
| `deliveryCost` | Стоимость доставки в валюте закупки. Пусто/0 — без распределения |
| `items[]` | Позиции — формат идентичен `trip.items[]` |
| `supplierPayments[]` | Оплаты поставщикам `{supId, amount, paidBy}` |
| `cm` | Комментарий |
| `history[]` | Журнал |

### Позиция `items[]`

Формат полностью совпадает с `trip.items[]`: `{supId, prodId, skuId, qty,
price, pu, fw, tc}`. `pu` — `"кг"` (по весу брутто) или `"тару"` (за ящик/мешок);
`fw` — фактический вес (если 0 — теоретический `qty × SKU.gw`); `tc` — стоимость
тары за единицу.

## Расчёт себестоимости (`calcPurchase`)

Без `rate` и без `expShare` рейса:

1. По позиции `tot = (pu==="тару" ? qty×price : вес×price) + qty×tc`.
2. Если `deliveryCost > 0` — распределяется **пропорционально весу**:
   `dShare = deliveryCost × (вес_позиции / общий_вес)`.
3. `totalCost = tot + dShare`.
4. `costPerUnit = тару ? totalCost/qty : totalCost/нетто-вес`.

При `deliveryCost = 0/пусто` себестоимость единицы = чистая закупочная цена.

## Партии FIFO (приёмка)

При сохранении закупки её партии в `trade-batches-v1` **пересоздаются**
(`source:"purchase"`, `purchaseId`, наследуют `projectId`/`officeId` от закупки,
`costPerUnit` из `calcPurchase`). Партии участвуют в FIFO-остатке и доставках
наравне с партиями рейсов (FIFO-функции source-agnostic).

**Guard:** если хотя бы одна партия закупки уже частично продана
(`qtyRem < qtyOrig`), редактирование позиций и удаление закупки заблокированы.

## Расчёты с поставщиком

Долг по закупке учитывается в модуле «Расчёты → Поставщики» (`SettlementsMod`,
`calcPurchaseData`): начислено = сумма `items[].tot`, оплачено =
`supplierPayments[]`. Отдельных записей `settlement` приёмка не создаёт (как у рейса).

> ⚠️ **Известное ограничение (Шаг 3 ADR-009):** суммы закупок складываются в
> баланс поставщика без различения валют. Для поставщиков с одной валютой
> корректно; мультивалютная отчётность — отложена на Шаг 3.

## Связь с накладной (Invoice)

`Invoice.linkedTo = {type:"purchase", id:"ЗК-NNN"}` — реализуется в Слое В
(сущность Invoice, [ADR-010](../../90-decisions/ADR-010-invoice-entity.md)).

## UI

Модуль навбара **«🛒 Закупки»** (`ProcurementMod`) с под-вкладками:
- **«Рейсы в Грузию»** — `TripsMod` (рейсы);
- **«Местные закупки»** — `PurchasesMod` (эта сущность).

Аналитика закупок по рейсам вынесена в отдельную вкладку **«📈 Аналитика закупок»**
(`OrdersAnalyticsMod`).
