# Batch — JSON-формат FIFO-партии

## Storage

- Ключ: `trade-batches-v1`
- JS-константа: `SK_BATCH`
- Содержимое: массив объектов

## Назначение

Логическая единица учёта на складе — порция товара, поступившая одним рейсом от одного поставщика. Создаётся автоматически при переходе [рейса](../../20-domain/sales-lifecycle.md) в статус "На складе". Каждая партия имеет **уникальную себестоимость**, зафиксированную в момент создания.

Списывается по правилу **FIFO** (First In First Out): при отгрузке клиенту сначала уменьшаются партии с самой ранней датой, потом более свежие. Это даёт **точную себестоимость каждой отгрузки**.

## Формат

```json
{
  "id": "B-XXXX",
  "source": "trip",
  "tripId": "Р-XXX",
  "officeId": "О-XXX",
  "prodId": "Т-XXX",
  "skuId": "SKU-XXX-XX",
  "qtyOrig": 50,
  "qtyRem": 35,
  "costPerUnit": 215.5,
  "unitLabel": "₽/кг",
  "date": "2026-04-28"
}
```

## Поля

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | ID партии, формат `B-XXXX` (4 цифры, ведущие нули) |
| `source` | string | Источник прихода. Сейчас всегда `"trip"`. В будущем для закупок вне рейса — другие значения (см. [GAP-009](../../00-meta/gaps.md)) |
| `tripId` | string | Ссылка на рейс прихода (`Р-XXX`) |
| `officeId` | string | На каком складе лежит |
| `prodId`, `skuId` | string | Что лежит |
| `qtyOrig` | number | Изначальное количество в **единицах SKU** (ящики/мешки/коробки) |
| `qtyRem` | number | Текущий остаток в единицах SKU. Уменьшается при отгрузках, увеличивается при возвратах |
| `costPerUnit` | number | Себестоимость единицы. Для весовых — ₽/кг (по нетто), для тарных — ₽/единица. Не меняется после создания |
| `unitLabel` | string | `₽/кг` для весовых (`tp=0`), `₽/ящ.` или `₽/меш.` для тарных (`tp=1`) |
| `date` | string | Дата прихода на склад (`YYYY-MM-DD`) |

## Жизненный цикл партии

1. **Создание** — автоматически при переходе рейса в "На складе". На один рейс — несколько партий (по одной на каждую позицию `trip.items[i]`). `costPerUnit` рассчитывается из `_costPerUnit` итемов рейса. `qtyOrig = qtyRem = факт. количество приёмки`.

2. **Списание** — при отгрузках через `fifoAllocate`: уменьшается `qtyRem` старейших подходящих партий до требуемого количества.

3. **Возврат** — при возвратах с доставки через `fifoReturn`: восстанавливается `qtyRem` тех же партий, из которых ранее списывалось.

4. **Полное списание** — когда `qtyRem = 0`, партия остаётся в массиве (для истории), но больше не участвует в FIFO-распределении.

## Атомарность

Партии создаются и обновляются **атомарно** при операциях с продажами и доставками. Не редактируются вручную через UI.

## Особые случаи

### Местные/российские поставщики
Сейчас партии создаются **только** через рейс. Для закупок вне рейса (от местных или российских поставщиков) механизм создания партии не реализован — см. [GAP-009](../../00-meta/gaps.md).
