# ADR-003: Контракт CC по ведению базы знаний

## Контекст

Максим — не программист и владелец бизнеса. Он **физически не может** помнить, где какие файлы лежат в `kb/` и что нужно обновить после каждого решения. Без чёткого распределения ответственности база знаний быстро устареет и потеряет свою ценность.

При этом ключевое требование Максима: *"чтобы ничего никогда не терялось"* — каждое решение зафиксировано, каждая связь проверена, каждое расхождение между документацией и кодом обнаружено.

## Решение

CC (Claude Code) принимает на себя **контракт по автоматическому ведению базы знаний** в составе **четырёх обязательств**:

### Обязательство 1. Автоматическое ведение
После каждого обсуждения CC сам:
- определяет, какие файлы затронуты
- обновляет их
- создаёт новые файлы при необходимости
- фиксирует решение в новом ADR
- обновляет [INDEX.md](../INDEX.md) и [CHANGELOG](../95-changelog/) если нужно

**Без команды от Максима.** Максим говорит "ок, принимаем" — документация обновляется сама.

### Обязательство 2. Консистентность связей
При изменении файла CC проверяет `referenced_by` (через front matter), обновляет зависимые файлы, добавляет новые термины в [glossary.md](../00-meta/glossary.md).

### Обязательство 3. Сверка с кодом
CC периодически (триггеры — перед значимым решением, перед началом большой темы, раз в месяц) проверяет, что описание в `kb/` соответствует реальному коду (`trade_app_v3.jsx`, `server.js`, БД). Расхождения **поднимает до фиксации**, не молчит. См. [code-sync-protocol.md](../00-meta/code-sync-protocol.md).

### Обязательство 4. Поиск белых пятен
CC регулярно обходит код и ищет функции/модули, которые есть, но не задокументированы. Записывает в [gaps.md](../00-meta/gaps.md).

## Последствия

### Положительные
- Максим работает с продуктом, а не с документацией. Это многократно повышает скорость работы.
- Документация остаётся актуальной без специальных усилий.
- Архитектор всегда получает свежий контекст, без передачи "сводок".
- Расхождения между кодом и документацией обнаруживаются регулярно, а не накапливаются годами.

### Отрицательные / компромиссы
- Качество ведения зависит от дисциплины CC в каждой сессии. Самопроверки нет, кроме как через front matter и читателей (Максим, Архитектор).
- При смене инструмента (например, переход с Claude Code на другой агент) — контракт нужно "перенять" новым исполнителем.

## Реализация

Детальный регламент 4 обязательств — в [00-meta/maintenance.md](../00-meta/maintenance.md). Это **обязательный** файл, который CC читает в начале сессии и при значимых действиях.

Дополнительные файлы:
- [00-meta/code-sync-protocol.md](../00-meta/code-sync-protocol.md) — Обязательство 3
- [00-meta/gaps.md](../00-meta/gaps.md) — очередь Обязательства 4
- [00-meta/conventions.md](../00-meta/conventions.md) — front matter, требуемый Обязательством 2

## Альтернативы, которые отклонили

### Максим вручную ведёт базу знаний
**Почему отклонили**: невозможно физически. 70+ файлов с десятками связей.

### Архитектор ведёт базу знаний
**Почему отклонили**: у Архитектора нет доступа на запись в репозиторий (он работает в браузере, без git).

### Без чёткого контракта (CC как-нибудь сам)
**Почему отклонили**: после 10 сессий правила работы расходятся. Без явного протокола — энтропия.
