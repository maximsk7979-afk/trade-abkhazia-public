# ADR-021: Ежедневные смешанные рейсы + заказ на день + единый каталог по проектам клиента

> **Поправка 2026-06-11 (Максим, старт торговли):** **ленивое авто-создание рейсов ОТМЕНЕНО** — все рейсы заводят только владелец/ГД; день заказа в мини-аппе доступен, только если на дату существует открытый рейс (отсечка — из рейса). Банановый лимит действует и в смешанной корзине. Поставка переходит на смешанные закупочные рейсы (банан+овощи одной машиной). Остальное (день-выбор, единый каталог, корзина) — в силе.


## Контекст

Бизнес перешёл на **ежедневные рейсы Грузия→Абхазия**, и в **одну машину грузятся товары разных проектов** одновременно: бананы (PRJ-004), турецкие овощи (PRJ-001), грузинские овощи (PRJ-003), местные (PRJ-002). Это меняет две базовые посылки прежней модели:

1. **[ADR-009](ADR-009-multitenancy-projects.md) п. 3** фиксировал «**Trip — рейс всегда внутри одного проекта**». Для смешанной машины это неверно.
2. **[ADR-020](ADR-020-order-intake-banana-pricing.md)** строил приём заявок «под конкретный рейс одного проекта (банан)», клиент выбирал рейс по дате из списка. При ежедневных рейсах удобнее выбирать **день доставки**, а ассортимент показывать **единым каталогом по проектам клиента**.

Решения приняты в сессии 2026-06-06 (диктовка Максима, по пунктам), после изучения базы и обсуждения развилок.

## Решение

### 1. Рейс — ежедневная смешанная машина (отменяет ADR-009 п. 3 «рейс = один проект»)

- Рейс перестаёт принадлежать одному проекту. Для приёма заказов рейс — это по сути **дата доставки + отсечка приёма**.
- На карточке рейса: `projectId: ""` (пусто) + признаки `mixed: true`, `auto: true`. Поле `projectId` для смешанного рейса не несёт смысла; принадлежность проекту определяется **на уровне строк** при закупке/отгрузке (см. п. 5).
- **Лимита вместимости нет** (решение 2026-06-06). Отсечка — только по времени. (Прежняя двойная отсечка ADR-020 п. 3 для бананов отменена в части «вместимость».)
- **Отсечка — накануне дня доставки в 20:00** (часовой пояс МСК, UTC+3). Приём на день D открыт, пока `сейчас ≤ (D−1) 20:00 МСК`.
- **Создание рейсов — ленивое авто.** Система не держит пустые рейсы заранее: рейс на дату создаётся автоматически при **первом заказе** на эту дату (поля выше + `arrDate`=дата, `cm:"Авто (ежедневный смешанный рейс)"`). Это шаг к «расписанию-константе» из [ADR-020](ADR-020-order-intake-banana-pricing.md) п. 1.2.

### 2. Заказ — на день, а не на конкретный рейс

- В мини-аппе вкладка «Заказ» открывает экран **«На какой день вы хотите сделать заказ?»** с **4 кнопками**: **завтра, +2, +3, +4** (с датами). День с прошедшей отсечкой — **неактивен** (пометка «приём закрыт»).
- Выбор дня → каталог → корзина. Заявка привязывается к рейсу выбранного дня (ленивое создание при оформлении).
- **Одна заявка на клиента на день**, редактируемая и отменяемая до отсечки.

### 3. Единый каталог по проектам клиента

- После выбора дня показывается **единый каталог** — все **активные** SKU (`active !== false`), у которых `applicableProjects ∩ проекты клиента ≠ ∅`.
- Клиент, привязанный только к проекту «Бананы» (PRJ-004), видит **только бананы**; клиент с овощными проектами — овощи (и бананы, если привязан к PRJ-004).
- **Сортировка секциями: Овощи → Фрукты → Бананы → Прочее**, внутри секции — по названию товара.
- Заменяет прежний экран «меню групп» ([mini-app.md](../40-system/mini-app.md)) и раздельные потоки «банан»/«весовые».

### 4. Цена — смешанная корзина (режим по позиции)

В одной заявке-корзине строки разных типов цены (по `pricingMode`, [ADR-020](ADR-020-order-intake-banana-pricing.md) п. 2.1):
- **Банан** — `volume-tier` (по сумме банановых ящиков в заявке), заказ в **ящиках**.
- **Овощи (весовые)** — **ручная ₽/кг по SKU** (владелец задаёт через Еву, [GAP-036](../00-meta/gaps.md#gap-036)), заказ в **упаковках**, сумма **ориентировочная** (точная — после взвешивания). Решение 2026-06-06: остаёмся на ручных ₽/кг (не на прайс-листе opt/mid/ret).
- **Тарные не-банановые** (картофель в мешках и т. п.) — пока **не цениру́ются**, в каталог не попадают ([GAP-040](../00-meta/gaps.md#gap-040)).
- Сумма заявки = сумма строк; цена замораживается при оформлении.

### 5. Проект строки присваивается при закупке, а не при заказе (уточнение к ADR-009 §6)

Один и тот же товар (напр. «Помидор кл.») в разные дни приезжает из **Турции** (PRJ-001) или **Грузии** (PRJ-003). Поэтому:
- `applicableProjects` у товара = **в каких проектах он бывает** — это **фильтр ассортимента** клиента, не учётная привязка.
- Строка заявки при заказе **не фиксирует** `projectId` (товар ещё не закуплен). Учётный `projectId` строки присваивается **при закупке/отгрузке** (отложенный «Шаг 3» [ADR-009](ADR-009-multitenancy-projects.md): per-line projectId + FIFO + маржа).
- **Распределение расходов смешанного рейса** по проектам (транспорт и пр.) — тоже «Шаг 3» ([ADR-009](ADR-009-multitenancy-projects.md) §7, `allocation`). Сейчас **не делается** (см. GAP).

## Последствия

### Положительные
- Модель совпала с реальностью: ежедневная машина возит всё, клиент заказывает на день из своего ассортимента.
- Единый каталог + смешанная корзина — клиент в одной заявке берёт и бананы, и овощи.
- Ленивое авто-создание рейсов убирает ручную рутину; шаг к расписанию-константе.
- `applicableProjects`-фильтр даёт ровно нужную изоляцию ассортимента по проектам клиента.

### Отрицательные / компромиссы
- **Учёт смешанного рейса не закрыт:** per-line `projectId`, FIFO, маржа и **распределение расходов** по проектам отложены («Шаг 3» ADR-009). Сейчас рейс корректен как **поверхность заказа**, но не как мультипроектная учётная единица — явно помечено GAP.
- **trade_app (админка) — минимум:** авто-рейсы появляются в KV; проверяем лишь, что админка их отображает. Полное оформление/учёт смешанных рейсов — отдельная сессия.
- Прежний банановый лимит вместимости отменён (ежедневные рейсы); защита «от перепродажи машины» теперь не действует — приемлемо при ежедневной закупке под заказ.
- Требует **ретега товаров по проектам** (`applicableProjects`) — иначе фильтр не изолирует ассортимент (закрывает хвост «Шаг 2» roadmap).

## Альтернативы, которые отклонили

- **Рейс остаётся одного проекта, несколько параллельных рейсов в день** — не отражает реальность (одна машина), усложняет клиенту выбор. Отклонили в пользу одного смешанного рейса на день.
- **Прайс-лист opt/mid/ret для овощей** (себестоимость+наценка) — отложили: на этапе обкатки остаёмся на ручных ₽/кг (проще, не зависит от наличия свежей себестоимости). Возврат к прайс-листу возможен позже.
- **Фиксация проекта строки при заказе** — невозможна: товар ещё не закуплен, источник (Турция/Грузия) неизвестен до закупки.
