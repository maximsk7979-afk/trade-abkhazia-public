# ADR-001: Git+GitHub для хранения кода и знаний

## Контекст

Локальная папка `~/Documents/trade_app/` не была git-репозиторием. История изменений сводилась к версионированным именам файлов (v3, v10). Параллельная работа Архитектора (через копипаст в браузере) и CC (через файлы на Маке) приводила к риску перезаписей и потерь.

Долгоживущий проект с двумя ИИ-агентами в роли разработчиков и многомесячной траекторией требует:
- полной истории изменений
- возможности отката
- общей точки доступа для Архитектора, CC и (в будущем) внешних разработчиков

## Решение

Принимаем **Git + GitHub** как способ хранения кода и базы знаний.

- **Один приватный репозиторий** на GitHub
- Внутри — две папки: `kb/` (база знаний) и `eva/` (код Евы, в перспективе)
- Архитектор читает актуальное состояние через web fetch по ссылкам, не копипасту
- CC работает локально, коммитит и пушит изменения

## Последствия

### Положительные
- Полная история, ревью, откат — стандартные git-операции
- Архитектор всегда видит актуальное состояние через GitHub URL — нет потерь при переходе между чатами
- Защита от случайной перезаписи параллельной работой
- Готовность к подключению внешних разработчиков

### Отрицательные / компромиссы
- Разовая настройка (~30 минут): GitHub-аккаунт, SSH-ключ, конфиг — выполнено 28.04
- Максиму нужно понимать минимум git-концепций (репо, коммит, пуш) — техническая работа на CC

## Альтернативы, которые отклонили

### Облачная папка (Dropbox / Google Drive / iCloud)
**Почему отклонили**: нет нормальной истории изменений; нет защиты от одновременной перезаписи; для кода Евы всё равно нужен git.

### Без версионирования
**Почему отклонили**: не масштабируется на долгий проект и команду из нескольких ИИ-агентов.

### Два отдельных репо для kb/ и eva/
**Почему отклонили** (см. также ADR-002): связность знаний и кода — на пользу. Атомарные коммиты "знание + код" возможны только в одном репо.
