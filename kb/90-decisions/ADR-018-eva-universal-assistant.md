# ADR-018: Ева как универсальный помощник — разговорный объём, лимиты, изоляция данных клиента

## Контекст

Ева работает на универсальной LLM (Claude). В тексте она способна не только вести продажи, но и быть **полезным собеседником на любые темы** (ответить на вопрос, посоветовать, найти информацию). Максим (2026-05-31) решил использовать это как **инструмент лояльности**: помощник, который помнит клиента как человека и помогает в жизни, — сильно привязывает и отличает компанию от конкурентов. Это согласуется с [vision.md](../50-agents/eva/vision.md) («собеседник, с которым приятнее, чем с живым менеджером») и с блоком 1 памяти клиента ([ADR-017](ADR-017-eva-memory-architecture.md), «Ева-друг»).

Открытый разговор **повышает риск утечки**: в свободном чате Еву проще выманить (социнженерия, prompt-injection) на коммерческую информацию о других клиентах или о компании. Поэтому решение об объёме помощника неотделимо от решения об **изоляции данных**.

## Решение

### 1. Объём — полноценный помощник + интернет
Ева отвечает на вопросы вне торговли и помогает по мелочи. Подключается **инструмент web-search** (у модели на Bedrock интернета нет «из коробки»). Реализация — [GAP-026](../00-meta/gaps.md#gap-026).

### 2. Мягкий лимит — характером, не обрубателем
Главный механизм границы — **персона «занятого друга»**: помогает охотно и **коротко**, но на крупные/долгие задачи (сочинения, код, домашка, работа за специалиста) **по-дружески отшучивается и возвращает к делу** — не объявляет «правил», а ставит границу тепло. Граница: **одолжение другу — да; работа вместо специалиста — нет.**

### 3. Маршрутизация моделей (контроль стоимости)
Лёгкую болтовню — на дешёвую модель (Haiku), торговлю и сложное — на Sonnet. Способ определения темы (классификатор-ход / дефолт-Haiku с эскалацией / тема в сессии) выбирается при реализации ([GAP-026](../00-meta/gaps.md#gap-026)).

### 4. Технический бэкстоп — только против выбросов
Считать объём off-topic на клиента (данные уже в `eva_messages`); при сильном превышении Ева по-дружески сворачивает. Не основной тормоз — страховка. Обязателен **алерт бюджета Bedrock** (закрывает урок [INC-001](../75-incidents/INC-001-bot-anthropic-balance.md), теперь обязателен).

### 5. Чувствительные темы — помогать с оговоркой
Здоровье / юридические / финансовые вопросы — отвечает по-дружески, но добавляет «это не замена специалиста, уточни у…»; без выдумок.

### 6. Изоляция данных клиента (критично)
**Клиент видит только своё.** Защита в несколько слоёв, главный — архитектурный:

- **Можно (про этого клиента):** его отпускные цены (по его уровню), его заказы/история, его баланс/долг, его доставки, доступный ему ассортимент.
- **Табу (всё остальное):** данные других клиентов (существование, заказы, цены, долги, контакты); закупочные цены, маржа, наценка; обороты/выручка/финансы компании; условия поставщиков, внутренние процессы, данные сотрудников; любая агрегированная коммерческая статистика. Тонкость: свою **отпускную** цену назвать можно, **закупочную/маржу** и чужие цены — никогда.

Как обеспечиваем:
1. **Архитектурная изоляция (главное):** клиент-facing инструменты физически отдают **только данные текущего клиента** (фильтр по его id зашит в инструмент). Нет ни одного клиент-facing инструмента, возвращающего cross-client/общефирменные данные. Не попало в контекст — нельзя слить, даже под давлением.
2. **Изоляция контекста:** грузится только B этого клиента и только его хвост A ([ADR-017](ADR-017-eva-memory-architecture.md)).
3. **Гейт по роли собеседника:** клиент → строгий клиент-скоуп; менеджер/owner → внутренний доступ разрешён (свои). Связано с RBAC.
4. **Жёсткий принцип в промпте** + явный отказ на попытки выманить (при настойчивости — зовёт менеджера). Ловит остаток и прямые попытки.

Реализация и проверка всех инструментов на изоляцию — [GAP-030](../00-meta/gaps.md#gap-030).

## Последствия

### Положительные
- Сильный драйвер лояльности: Ева — повод открыть Telegram не только за овощами → больше касаний → больше продаж.
- Усиливает блок 1 памяти («друг») — помощник, который помнит и помогает, максимально липкий.
- Маршрутизация моделей держит стоимость болтовни почти на нуле.
- Архитектурная изоляция делает утечку чужих данных невозможной по конструкции, а не «по инструкции».

### Отрицательные / компромиссы
- Переменная стоимость растёт (токены + поисковые запросы), ориентир ~$150–300/мес при текущем размере; управляется лимитами и выбором модели. Инфраструктурно — почти ноль прироста.
- Риск злоупотребления (использовать как бесплатный ChatGPT) — снимается персоной + бэкстопом.
- Репутационный риск на чувствительных темах — снижается дисклеймерами.
- Открытый чат = поверхность для социнженерии — закрывается архитектурной изоляцией.

## Альтернативы, которые отклонили

### Только торговля, без off-topic
**Почему отклонили**: теряем мощный лоялти-бонус; не используем то, за что уже платим.

### Жёсткие лимиты как основной механизм
**Почему отклонили**: «лимит исчерпан» рушит тёплый UX; персона + дешёвая модель решают 95% без счётчиков.

### Конфиденциальность только инструкцией в промпте
**Почему отклонили**: не булетпруф против социнженерии/prompt-injection; нужна архитектурная изоляция (данные просто не попадают в контекст клиента).
