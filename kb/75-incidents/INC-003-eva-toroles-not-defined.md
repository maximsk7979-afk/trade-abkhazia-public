# INC-003: Ева падала на каждом сообщении — `toRoles is not defined`

## Что произошло

После деплоя ролевого слоя RBAC ([ADR-022](../90-decisions/ADR-022-role-model-rbac.md), коммит `36327df`, выложен ~08–09.06) Ева **переставала отвечать на любое сообщение** и присылала аварийный фолбэк:

> «Ой, что-то пошло не так с моей стороны. Сейчас разберусь.»

В прод-логах (`pm2 logs eva`) — на каждое входящее:
```
[ERR] claude error chatId=...: toRoles is not defined
```

Сбой был **полным** (Ева не отвечала никому), но **тихим** — процесс `eva` оставался `online` в pm2 (ошибка ловилась внутри конвейера и отдавалась фолбэком), поэтому мониторинг здоровья процесса инцидент не показал. Обнаружено только когда Максим написал Еве и получил фолбэк (скрин из Telegram 10.06 16:45).

## Когда обнаружено

2026-06-10, ~16:45 (груз. время). Фактически Ева была нерабочей с момента деплоя RBAC (~08–09.06) — все сообщения за этот период падали.

## Затронутые компоненты

- `eva` (PM2-процесс) — рантайм Евы
- `/var/www/eva/src/tools/index.js` — сборка схем инструментов (`getSchemas`)
- `/var/www/eva/src/tools/access.js` — RBAC-хелперы (включая `toRoles`)

## Корневая причина

В `tools/index.js` функция `getSchemas` использует `toRoles(roles)` (фильтрация инструментов по ролям собеседника), но строка импорта из `./access` это слово **не подключала**:

```js
// было (сломано):
const { accessOf, roleAllowed } = require("./access");
...
const rs = toRoles(roles);   // ReferenceError: toRoles is not defined
```

`toRoles` корректно **определён и экспортирован** в `access.js` — то есть это чистая ошибка пропущенного импорта, внесённая при рефакторинге RBAC (`36327df`: inline-функции `accessOf/roleAllowed` вынесены в `access.js`, импорт добавлен без `toRoles`). `getSchemas` вызывается при сборке **каждого** запроса к LLM → падало любое сообщение.

Латентность: баг существовал в репозитории с `36327df`; на проде проявился сразу после деплоя RBAC. В сессии 10.06 он был замечен «по коду» и **уже исправлен в репозитории** (коммит `0c3db7c`, добавлен `toRoles` в импорт), но на прод фикс не выкладывался — на проде продолжала работать сломанная версия.

## Что сделали

2026-06-10, восстановление (Claude Code, доступ по root-паролю через `sshpass`):

1. **Подтвердили** корневую причину по прод-логам (`toRoles is not defined` на каждое сообщение) и по боевому файлу (строка 51 без `toRoles`, строка 56 его использует; `access.js` экспортирует `toRoles`).
2. **Бэкап**: `/var/www/eva/src/tools/index.js.bak-toRoles-20260610`.
3. **Фикс** строки импорта: `const { accessOf, roleAllowed, toRoles } = require("./access");`.
4. `node --check` — чисто; `pm2 restart eva` — online.
5. **Smoke-тест** прямого вызова `getSchemas` на проде — без `ReferenceError`, ролевая фильтрация корректна (owner→12 инструментов, client→5, buyer→9, gen_director→9, supplier→2).
6. Максим подтвердил вживую: Ева отвечает нормально.

Прод приведён в соответствие с репозиторием (фикс там уже был — `0c3db7c`).

## Уроки

1. **Деплой ≠ «закоммичено».** Фикс был в репозитории с момента обнаружения, но прод оставался сломанным сутки, потому что выкладку отложили. Любой фикс боевого бага должен либо немедленно выкладываться, либо явно фиксироваться как открытый прод-хвост в roadmap/gaps. (См. протокол закрытия сессии — п. «если код менялся — задеплоен на VPS».)
2. **Тихие сбои нужно ловить health-check'ом, а не только статусом процесса.** `eva` оставалась `online`, отвечая фолбэком всем. Нужен внешний синтетический пинг: периодически слать Еве тестовое сообщение и проверять, что ответ — не аварийный фолбэк (или считать частоту `[ERR] claude error` в логах и алертить владельцу). → кандидат в GAP/мониторинг.
3. **Smoke-тест ключевого пути после деплоя.** `getSchemas` — на критическом пути каждого сообщения; его прямой вызов (без Telegram-трафика) детерминированно ловит такие `ReferenceError`. Добавить в чек-лист деплоя Евы: после рестарта прогнать `node -e "require('./src/tools').getSchemas(['client'])"`.
4. **`node --check` не ловит `ReferenceError`** (это рантайм, не синтаксис). Поэтому нужен п.3 — реальный вызов, а не только проверка синтаксиса.
