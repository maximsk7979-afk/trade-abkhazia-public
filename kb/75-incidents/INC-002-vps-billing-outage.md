# INC-002: VPS отключён из-за просрочки оплаты Vultr

## Что произошло

2026-05-08 вечером Максим обнаружил, что https://trade-abkhazia.com не открывается. CC провёл диагностику снаружи:

- DNS отвечает корректно: `trade-abkhazia.com → 108.61.167.168`
- Ping не проходит (100% packet loss)
- TCP-порты 22, 80, 443 — все таймаутят одновременно
- Значит проблема не в Nginx / SSL / коде / БД — машина целиком недоступна по сети

Причина: на счету Vultr закончились средства, провайдер остановил инстанс.

## Затронутые компоненты

VPS целиком: фронт, API, БД, бот — всё было недоступно для всех пользователей.

## Резолюция

Максим оплатил счёт Vultr → инстанс автоматически поднялся. Внешняя проверка через ~30 минут после оплаты:
- HTTPS-запрос отдаёт код 200, статика отдаётся
- TLS 1.3 + Let's Encrypt-сертификат, действителен до 2026-06-07
- Время ответа ~270 мс

Внутренние сервисы (PM2 / Postgres / cron) специально не проверялись — Максим подтвердил, что приложение работает.

## Урок

Это **тихий single point of failure**: без мониторинга баланса Vultr продакшен падает в любой момент. Если карта истечёт или средств не хватит — сайт умирает, оповещения нет, обнаруживается только когда пользователь сам пытается зайти.

## Рекомендации (не выполнены)

- [ ] Настроить автоплатёж в панели Vultr или хотя бы email-оповещения о низком балансе
- [ ] Внешний мониторинг доступности (UptimeRobot / Healthchecks / Better Stack) — чтобы узнавать о падении первым, а не от Максима из браузера
- [ ] Зафиксировать в [70-operations/infrastructure.md](../70-operations/infrastructure.md) Vultr-аккаунт как критичную зависимость
