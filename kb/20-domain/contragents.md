# Контрагенты

## Что такое контрагент

Сторонняя сторона, с которой у нас есть деловые отношения и которая **не подпадает** под другие категории сторон ([Клиент](../00-meta/glossary.md#клиент), [Поставщик](../00-meta/glossary.md#поставщик-supplier), [Партнёр](../00-meta/glossary.md#партнёр-по-рейсу--partner)). По сути — все прочие, с кем мы взаимодействуем по деньгам.

В отличие от поставщика, контрагент **не продаёт товар**, а оказывает услугу или взимает платежи.

## Хранение

- **Storage**: `trade-cat-contragents`
- **JS-константа**: `SK_CONT`
- **JSON-формат**:
  ```json
  { "id": "КА-XXX", "n": "Имя/название", "cat": "категория" }
  ```

## Категории контрагентов

Поле `cat` определяет категорию. Перечень открыт — будет расширяться по мере появления новых типов отношений.

### Текущие категории (используются в системе)

| `cat` | Описание | Связь с расходами |
|---|---|---|
| `buyer` | Закупщик в Грузии (физическое лицо, ведущее закупки на оптовых рынках) | Статья расхода рейса `buyer` (валюта GEL) |
| `transport` | Водители машин из Грузии в Абхазию | Статья расхода рейса `transport` (валюта RUB) |
| `expeditor` | Экспедитор — сопровождает груз на границе | Статья расхода рейса `expeditor` (валюта RUB) |
| `customs` | Таможня / таможенный брокер | Статья расхода рейса `customs` (валюта RUB) |
| `border` | Погранслужбы | Статья расхода рейса `border` (валюта RUB) |
| `loader` | Грузчики (в Грузии или в Абхазии) | Статьи `loader` (GEL, в Грузии) и `loaderAbh` (RUB, в Абхазии) |

### Планируемые категории (в перспективе)

Эти категории появятся по мере роста бизнеса. Сейчас в системе **не реализованы**, требуют доработки UI и расходных категорий.

| Возможный `cat` | Описание | Когда понадобится |
|---|---|---|
| `landlord` | Арендодатель склада | Аренда склада — сейчас не учитывается отдельно |
| `tax` | Налоговая (РФ, Грузия, Абхазия) | Налоговые платежи, начисления |
| `accountant` | Внешний бухгалтер | Услуги бухгалтерии |
| `lawyer` | Юрист / юридические услуги | Договоры, споры |
| `bank` | Банки, платёжные системы, эквайринг | Комиссии за обслуживание |
| `delivery_transport` | Перевозчик внутри Абхазии (если есть отдельный от рейса) | Сейчас доставка идёт нашими силами |

При появлении новой категории — её нужно:
1. Добавить в этот реестр
2. Если нужно — добавить новую статью расхода в `EXP_TYPES` (см. [20-domain/settlements/](settlements/))
3. Если требуется UI-фильтр — расширить интерфейс справочника

## Особые случаи

### Махо (КА-001) — двойная сущность
Махо одновременно:
- **Сотрудник** (`trade-cat-staff` запись С-003, роль `buyer`)
- **Контрагент** (`trade-cat-contragents` запись КА-001, категория `buyer`)

Это **не дубликат**: как сотрудник он один (С-003), как получатель платежей за услуги закупки — это контрагент КА-001. Двойная сущность объясняется тем, что Махо — внешний (не в штате), но регулярный участник процесса. Видеть его и в команде, и в реестре подрядчиков — оправдано.

См. [15-team/maho.md](../15-team/maho.md).

### Лия — НЕ контрагент
Лия — **партнёр** по рейсу, отдельная категория (см. [glossary](../00-meta/glossary.md#партнёр-по-рейсу--partner)). В `trade-cat-contragents` её нет. Расчёты с ней ведутся в отдельной модели (см. [20-domain/settlements/liya-partner.md](settlements/liya-partner.md)).

## Связь с финансами

### Через `trip.expenses[]`
Каждая статья расхода рейса имеет `contragentId`. При расчёте балансов автоматически:
- Если `paidBy === "Партнёр"` — баланс контрагента считается закрытым (Лия заплатила сама)
- Если `paidBy === "Мы"` — долг перед контрагентом висит до ручного `payment`

См. подробно [settlements/liya-partner.md](settlements/liya-partner.md), раздел 6.

### Через `settlements` (ручные операции)
Запись в `trade-settlements-v2` с `acctType: "expense"` и `contragentId: "КА-XXX"` фиксирует:
- Оплату контрагенту (`opType: "payment"`)
- Ручное начисление (`opType: "charge"`)

См. [40-system/data-formats/settlement.md](../40-system/data-formats/settlement.md).

## Открытые вопросы

См. [gaps.md](../00-meta/gaps.md):
