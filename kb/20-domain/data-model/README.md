# Логическая модель данных

Описание сущностей системы как абстракций — без привязки к JSON или БД.

> ⏳ Заглушка. Сущности будут описаны постепенно по нашему стартовому набору:
> продажа, рейс, доставка, партия, клиент, сотрудник, контрагент, поставщик, офис, товар, SKU, складская операция, взаиморасчёт.

## Что будет внутри

- **entities.md** — описание каждой сущности (атрибуты, виды, связи, бизнес-правила)
- **relationships.md** — диаграмма связей между сущностями
- **id-conventions.md** — формирование ID (ПС-XXX, Р-XXX, B-XXXX, и т.д.)
- **lifecycle.md** — жизненные циклы (статусы рейса, продажи, и т.д.)

## Связь с физической моделью

Логическая модель здесь, физический формат (JSON) — в [40-system/data-formats/](../../40-system/data-formats/). Связь — через ссылки в каждой сущности.

См. [ADR-002](../../90-decisions/ADR-002-modular-knowledge-base.md), пункт о разделении логической и физической модели.
