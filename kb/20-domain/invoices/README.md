# Накладные поставщиков

База знаний для распознавания накладных поставщиков (грузинских рукописных, в будущем — других). Используется Евой при работе с фото накладных. Связана с сущностью `Invoice` ([ADR-010](../../90-decisions/ADR-010-invoice-entity.md)).

## Структура (по [ADR-011](../../90-decisions/ADR-011-eva-supplier-segmentation.md))

```
invoices/
├── README.md                 ← этот файл
├── _common/                  ← общий слой (универсальное для всех поставщиков)
│   ├── README.md
│   ├── georgian-alphabet.md
│   ├── invoice-structure.md
│   ├── arithmetic-verification.md
│   ├── number-formats.md
│   └── ocr-common-issues.md
├── suppliers/                ← per-supplier полные локальные базы
│   ├── README.md
│   └── p-004-zaza/           ← Заза, оптовый склад в Батуми
│       ├── profile.md
│       ├── dictionary.md
│       ├── recognition-rules.md
│       ├── format.md
│       ├── handwriting.md
│       ├── price-ranges.md
│       └── examples/
│           └── README.md
├── extraction-prompts.md     ← инструмент: запросы для выгрузки знаний из обученных чатов
└── examples/                 ← общий золотой датасет (cross-supplier регрессия)
    └── README.md
```

## Слои

| Слой | Что туда идёт | Когда обновлять |
|---|---|---|
| `_common/` | Универсальное для всех грузинских рукописных накладных: алфавит, структура строки, арифметика, форматы чисел, общие OCR-проблемы | Только при наблюдённой одинаковости у ≥2 поставщиков (см. [ADR-011 п. 6](../../90-decisions/ADR-011-eva-supplier-segmentation.md)) |
| `suppliers/<id>/` | Полная локальная база поставщика: словарь, правила сорта, эвристики, формат, почерк, цены, примеры. Дублирование терминов между поставщиками допустимо | При появлении нового поставщика и при накоплении знаний по существующему |
| `examples/` (верхний) | Общий золотой датасет для регрессии Евы — включает примеры разных поставщиков | По мере появления эталонов |
| `extraction-prompts.md` | Готовые тексты запросов для выгрузки знаний из обученных Claude-чатов в новые папки `suppliers/<id>/` | По мере появления новых поставщиков с обученным чатом |

- **Эталонные накладные** (`examples/`) — пока пусто. План сбора 10–15 эталонов — следующая сессия

## Жизненный цикл базы знаний

По [ADR-012](../../90-decisions/ADR-012-eva-self-learning-plan.md) — три этапа самообучения Евы:
1. **Этап 1 MVP** (текущий): база заполняется вручную (через CC), Ева делает черновик, человек правит, в базу автоматически ничего не идёт
2. **Этап 2 полуавтомат** (после ~50 распознанных Invoice): Ева формирует дайджест предложений на основе паттернов исправлений
3. **Этап 3 автомодерация** (без жёсткого срока): очевидные случаи (новые термины с явной частотой, ценовые диапазоны) идут в базу автоматически
