# Учёт совместных закупок и взаиморасчётов с Лиёй

Документ описывает механику учёта совместных рейсов с партнёром-перевозчиком **Лия**: разделение транспортных расходов, расчёты со сторонними контрагентами и взаиморасчёты Максим ↔ Лия.

> Источник истины кода: `trade_app_v3.jsx`, функции `calcTripG`, `calcTripData`, `getPartnerData`, `getExpenseSummary`, `getSupplierDetail`.

## 1. Двойная роль Лии

Лия одновременно выступает в **двух разных ролях**, которые в системе учитываются раздельно:

### 1.1 Партнёр по рейсу (acctType: "partner")
- Не контрагент, не имеет ID `КА-XXX`.
- Хранится в массиве `trip.partners[]` как `{name: "Лия", weight: "..."}`.
- С ней делятся транспортные и сопутствующие расходы рейса пропорционально весу.
- Балансы по совместным рейсам ведутся в модуле "🤝 Партнёр" взаиморасчётов.

### 1.2 Клиент-покупатель К-006 (acctType: "client")
- Запись в `trade-cat-clients`: `{id:"К-006", n:"Лия", pt:"opt"}`.
- Покупает у нас товар по оптовой цене.
- Учёт по линии "клиент" идёт независимо от линии "партнёр".

> ⚠️ Эти две сущности **никак не связаны технически**. Балансы не пересекаются. Это сознательное архитектурное решение.

## 2. Базовая модель совместного рейса

В каждом рейсе Р-XXX:
- **Наш товар** — описывается в `trip.items[]`, вес `trip.ourWeight` (кг).
- **Товар Лии** — в наших `trip.items[]` НЕ хранится (Лия ведёт свой учёт сама), указывается только её суммарный вес `trip.partners[i].weight`.
- **Машина одна**, едет вместе → транспортные и сопутствующие расходы делятся пропорционально весу.
- **Курс лари** общий: `trip.rate` (формула: `rate = 1000 / trip.rate`).

## 3. Структура данных рейса

### Поля, относящиеся к Лии

```json
{
  "id": "Р-001",
  "ourWeight": "2446",
  "partners": [
    { "name": "Лия", "weight": "2693" }
  ],
  "expenses": [
    { "key": "transport", "amount": "30000", "paidBy": "Партнёр", "contragentId": "КА-008" },
    { "key": "expeditor", "amount": "2500",  "paidBy": "Мы",      "contragentId": "КА-002" },
    ...
  ]
}
```

### Описания полей

| Поле | Назначение |
|---|---|
| `partners[]` | Массив партнёров рейса. На сегодня всегда одна запись `{name:"Лия", weight:"..."}` |
| `partners[i].weight` | Вес товара партнёра в кг (строкой) |
| `ourWeight` | Наш вес в кг (строкой) |
| `expenses[i].paidBy` | `"Мы"` или `"Партнёр"` — кто фактически отдал деньги |
| `expenses[i].contragentId` | ID контрагента-получателя (КА-001..КА-009) |

См. полный формат в [40-system/data-formats/trip.md](../../40-system/data-formats/trip.md).

## 4. Справочник статей расходов рейса

См. константу `DEF_EXP_TYPES` в коде:

```js
[
  { key: "transport",  label: "Транспортировка",     cur: "RUB" },
  { key: "buyer",      label: "Закупщик",            cur: "GEL" },
  { key: "loader",     label: "Грузчик",             cur: "GEL" },
  { key: "expeditor",  label: "Экспедитор",          cur: "RUB" },
  { key: "customs",    label: "Таможня",             cur: "RUB" },
  { key: "border",     label: "Погранслужбы",        cur: "RUB" },
  { key: "loaderAbh",  label: "Грузчик в Абхазии",   cur: "RUB" }
]
```

- `cur: "GEL"` — статьи в лари, конвертируются в рубли по `trip.rate`.
- `cur: "RUB"` — статьи сразу в рублях.
- `paidBy` принимает только `"Мы"` или `"Партнёр"`.

## 5. Алгоритм расчёта долей

### Шаг 1. Курс и веса
```
ri    = parseFloat(trip.rate)            // например, 34.2
rate  = 1000 / ri                         // RUB за 1 GEL
oW    = parseFloat(trip.ourWeight)        // наш вес, кг
pW    = Σ trip.partners[i].weight         // вес Лии, кг
tW    = oW + pW                           // суммарный
oS    = oW / tW                           // наша доля (0..1)
pS    = pW / tW = 1 - oS                  // доля Лии
```

### Шаг 2. Перевод расходов в рубли
```
для каждой статьи e:
   amountRUB = (cur=="GEL") ? e.amount * rate : e.amount
```

### Шаг 3. Постатейный расчёт долгов

Для каждого `expense` отдельно:
```
если e.paidBy === "Партнёр" и oS > 0:
    // Лия отдала деньги контрагенту
    // → Мы должны Лие нашу долю
    ourPart = round(amountRUB × oS)
    diff = -ourPart  (минус — растёт долг ПЕРЕД Лиёй)

если e.paidBy === "Мы" и pS > 0:
    // Мы заплатили контрагенту
    // → Лия должна нам её долю
    partPart = round(amountRUB × pS)
    diff = +partPart  (плюс — Лия должна нам)
```

### Шаг 4. Кумулятивный баланс

Все строки сортируются по дате, складываются `diff` нарастающим итогом:
- **bal > 0** → Лия должна нам
- **bal < 0** → мы должны Лие

Плюс ручные операции из `trade-settlements-v2` с `acctType: "partner"`.

## 6. Расчёты с третьими контрагентами

Логика автозакрытия:

| Кто оплатил рейсу | Что происходит с балансом контрагента |
|---|---|
| `paidBy = "Партнёр"` (Лия) | charged + paid начисляются одновременно → баланс перед контрагентом = 0. Долг только перед Лиёй (через partner-расчёт) |
| `paidBy = "Мы"` | Только charged. Долг перед контрагентом висит до ручного `payment` в "🔧 Расходы" |

## 7. Расчёты с поставщиками товара

**Закупка не делится** между нами и Лиёй. Это полностью наша закупка, наш товар, наш долг перед поставщиком. Лия со своими поставщиками рассчитывается сама и в нашей системе не учитывается.

Поля рейса для расчётов с поставщиком:
- `trip.items[]` — наши закупки (с `supId`)
- `trip.supplierPayments[]` — наши платежи поставщикам

## 8. Отчётность

Модуль "🤝 Партнёр" во Взаиморасчётах:
- список рейсов с балансом
- ручные операции
- кумулятивный итог "Мы должны Лие" / "Лия должна нам"

Drill-down по рейсу: параметры, постатейная таблица, экспорт HTML "Акт сверки" и "Сверка по рейсу".

## 9. Инварианты и краевые случаи

1. **Один партнёр на рейс** по факту, но архитектура (`partners[]` как массив) допускает несколько.
2. **Ноль партнёров** → все расходы наши, рейс не порождает строк во взаиморасчётах.
3. **Расход с пустым amount** (`""` → 0) — игнорируется.
4. **Округление**: `Math.round(rub × share)` на каждой строке. Микро-копейки могут терять копейку (≤1 ₽ на статью).
5. **Курс трактуется как обратный**: `rate = 1000 / trip.rate`.

## 10. Карта источников данных

| Что нужно | Где взять |
|---|---|
| Список рейсов | `trade-trips-v8` |
| Доля Лии в рейсе | `trip.partners[]` + `trip.ourWeight` |
| Расходы рейса и кто платил | `trip.expenses[]` |
| Курс рейса | `trip.rate` |
| Ручные операции с Лиёй | `trade-settlements-v2`, `acctType="partner"` |
| Ручные операции с контрагентами | `trade-settlements-v2`, `acctType="expense"` |
| Лия как клиент (продажи) | `trade-cat-clients` К-006 + `trade-sales-v1` |

## 11. Правила для будущих изменений

1. При создании нового рейса — `partners: [{name:"Лия", weight:""}]` (см. `mkTrip`).
2. `paidBy` — ровно `"Мы"` или `"Партнёр"`. Никаких других строк.
3. Если `paidBy="Партнёр"` — контрагент в "Расходах" автозакрывается.
4. Если `paidBy="Мы"` — контрагент остаётся должником до ручного `payment`.
5. Долг Мы↔Лия — побочный эффект paidBy. Ручных проводок при создании рейса не нужно.
6. Закупка товара (`items[]`, `supplierPayments[]`) — к Лие отношения не имеет.
7. Лия как клиент К-006 — отдельная линия, балансы не пересекаются.
8. Все суммы — строкой; парсятся через `parseFloat || 0`.
