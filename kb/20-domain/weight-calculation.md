# Правила расчёта весов и сумм

Описание формул для расчёта нетто-веса, брутто-веса, сумм по строке товара и по строке закупки.

## Виды товаров

В справочнике SKU поле `tp`:
- `tp = 0` — **весовой товар** (продаётся на вес)
- `tp = 1` — **тарный товар** (продаётся поштучно/ящиками без взвешивания)

| Т-027 | Банан DOLE | SKU-027-01 | карт. 20кг |
| Т-028 | Банан FP | SKU-028-01 | карт. 20кг |

## Поля строки товара (sale-line, shipment-line)

| Поле | Весовой (`tp=0`) | Тарный (`tp=1`) |
|---|---|---|
| `qty` | `""` (пусто) | количество штук строкой |
| `qtyTar` | количество ящиков строкой | `""` (пусто) |
| `wBrutto` | расчётный/фактический брутто строкой | `""` (пусто) |
| `price` | цена строкой | цена строкой |

## Сокращения упаковки в названии SKU (`nm`)

Поле `nm` у SKU кодирует упаковку сокращением + вес. Расшифровка (используется Евой в прайс-листе клиенту, детерминированно — `code/eva/src/client-data.js packagingLabel`):

| Сокращение | Расшифровка |
|---|---|
| `карт.` | Картонный ящик |
| `пл.` | Пластиковый ящик (**не** «плёнка») |
| `дер.` | Деревянный ящик |
| `мешок` | Мешок |

Пример: `пл.14кг` → «Пластиковый ящик 14 кг». В диалогах с клиентом товар называется **полным** именем (`product.fn`, напр. «Помидор классический»), упаковка — расшифровкой выше.

## Поля SKU, используемые в расчётах

| Поле | Смысл |
|---|---|
| `gw` | gross weight — вес **одного ящика** брутто (из справочника) |
| `tw` | tare weight — вес **одной тары** (одного ящика) |
| `tp` | тип товара: `0` весовой / `1` тарный |

## Формулы для строки продажи (`calcLineT` в коде)

### Тарный товар
```
total = qty × price
```
`wBrutto` не используется. Вес не учитывается в сумме.

### Весовой товар
```
netto = max(0, wBrutto − qtyTar × tw)
total = netto × price
```

Защита `max(0, …)` от отрицательных значений (если случайно введут брутто меньше тары).

## Формулы для строки закупки рейса (`calcItemG` в коде)

В рейсе есть **дополнительный механизм** теоретического vs фактического веса.

### Поля строки закупки

| Поле | Смысл |
|---|---|
| `qty` | количество ящиков |
| `price` | цена закупки за единицу |
| `pu` | unit для цены: `"тару"` (за ящик) или `"кг"` (за кг) |
| `fw` | fact weight — фактический вес из накладной (если известен) |
| `tc` | дополнительная стоимость на единицу |

### Расчёт

```
thW = qty × gw                       // теоретический вес (qty ящиков × вес одного ящика)
w   = (fw > 0) ? fw : thW            // если фактический указан — берём его, иначе теоретический
nw  = w − qty × tw                    // нетто-вес
```

### Сумма закупки строки

Если цена за тару (`pu === "тару"`):
```
tot = qty × price + qty × tc
```

Если цена за кг (`pu === "кг"`):
```
tot = w × price + qty × tc
```

## Формула брутто из нетто (для фото-накладных)

В CONTEXT.md упоминалась формула обратного направления:
```
брутто = нетто + (qtyTar × tw)
```

Используется при обработке фото-накладных, где исходный вес — нетто. **В коде явно не реализована** — это бизнес-правило для бота/Евы при распознавании.

## Разделитель дробей — точка и запятая равнозначны

В функции `pN(s)` (после фикса 2026-04-28):
- `pN("5.8")` → `5.8` ✅
- `pN("5,8")` → `5.8` ✅

Запятая внутри функции автоматически заменяется на точку перед `parseFloat`. То же сделано для `fmt(n)`. См. закрытый [GAP-007](../00-meta/gaps.md).

## Связь с моделью данных

- Поля `qty`, `qtyTar`, `wBrutto`, `price` есть в:
  - `saleData.lines[]` для ПС (см. [sale.md](../40-system/data-formats/sale.md))
  - `shipment[]` для ЗД и ЗР
  - `trip.items[]` для рейса (но добавляются `fw`, `tc`, `pu`)
