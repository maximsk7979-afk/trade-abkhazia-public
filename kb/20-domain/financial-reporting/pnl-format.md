# P&L — форма и структура

> Каркас отчёта о прибылях и убытках финблока (этап **Ф-3**). Группы статей согласованы с владельцем
> 2026-06-19 («берём за основу»); наполнение статьями — следующий шаг. **Статус — draft.**

## Принцип: две ортогональные оси

Каждая статья дохода/расхода имеет **две независимые координаты**:

- **Группа** (A/B/C) — *какой природы* доход/расход → определяет **место в P&L** (на каком уровне
  прибыли вычитается). Даёт многоуровневую прибыль (валовая → операционная → чистая).
- **Ось аналитики** — *к чему относится*: **проект** (`projectId`, сквозной по
  [ADR-009](../../90-decisions/ADR-009-multitenancy-projects.md)) и **офис** (`officeId`). P&L
  строится **в разрезе** этих осей и сводно.

## Группы статей (верхний уровень)

| | Группа | В P&L? | Природа |
|---|---|---|---|
| **A** | **Доходы** | да | что бизнес заработал |
| **B** | **Расходы** | да | что потратил на работу |
| **C** | **Движения капитала / обязательств** | **нет** | не заработок и не трата — перемещение собственных/заёмных денег |

> Группа **C вне P&L намеренно**: вклад владельца ≠ доход, возврат займа ≠ расход. Иначе прибыль врёт.

### Подгруппы

- **A1** Выручка от продаж *(основная — продажа товара)* — ✅ есть (`sales`)
- **A2** Прочие доходы — ✅ подтв.: **ретроспективный пересмотр цен** (ретробонусы/корректировки в нашу пользу), несёт `projectId`. ⏳ при наполнении уточнить: чья цена — поставщика (→ уменьшение COGS / ретробонус) или клиента (→ корректировка выручки)
- **B1** Себестоимость (COGS): закупка + расходы **рейса** (`trade-cat-exptypes`) — ✅ есть (FIFO + GAP-060)
- **B2** Усышка *(потери веса, отдельной строкой)* — ⏳ [GAP-054](../../00-meta/gaps.md#gap-054)/[GAP-055](../../00-meta/gaps.md#gap-055)
- **B3** Операционные расходы (opex) — **вне рейса**: ЗП, аренда, связь, ПО — ⏳ наполняется
- **B4** Финансовые расходы — ✅ подтв.: **проценты по займам** (+ банк. комиссии с безналом)
- **B5** Налоги — ✅ заложить статьи на будущее (платежей пока нет, появятся скоро)
- **C1** Капитал владельца (вклады/изъятия/дивиденды) — ✅ спроектирован ([treasury-design](treasury-design.md))
- **C2** Заёмные средства (**тело** займов полученных, вне P&L) — ✅ по кредиторам раздельно; **проценты → B4**
- **C3** Займы выданные (тело, актив, вне P&L) — ✅ мы даём в долг по заёмщикам раздельно; **проценты получаем → A2 `interest_income`**

## Форма P&L (waterfall)

```
A1  Выручка от продаж
−B1 Себестоимость (COGS)        ← закупка + расходы рейса
═══════════════════════════
=   ВАЛОВАЯ ПРИБЫЛЬ
−B2 Усышка
−B3 Операционные расходы (opex) ← вне рейса
═══════════════════════════
=   ОПЕРАЦИОННАЯ ПРИБЫЛЬ
+A2 Прочие доходы               ← бонус поставщика, возврат НДС (не от основной торговли)
−B4 Финансовые расходы
−B5 Налоги
═══════════════════════════
=   ЧИСТАЯ ПРИБЫЛЬ → дивиденды (C1) или остаётся в капитале
```

> **A2 «прочие доходы» стоит НИЖЕ операционной прибыли** (а не в верхней строке выручки) — это
> доходы не от основной торговли (бонус поставщика, возврат НДС), и в валовую/операционную маржу
> товара они не входят, чтобы не искажать доходность самой торговли.

## Проектная (и офисная) ось — обращение с общими расходами

| Тип статьи | Привязка к проекту/офису |
|---|---|
| **Прямые** (A1 выручка, B1 COGS, B2 усышка) | напрямую — продажа и рейс уже несут `projectId`/`officeId` |
| **Общие** (B3 opex, B4 финрасходы, B5 налоги, C капитал) | относятся к **бизнесу в целом** / нескольким проектам |

**✅ Выбор владельца (2026-06-19): Вариант 1 — двухуровневый P&L.** Allocation (Вариант 2) — позже.
1. **Двухуровневый P&L** *(выбрано):* проектный уровень = маржа до общих расходов
   (`Выручка − COGS − Усышка`); общие (opex/фин/налоги) вычитаются на уровне бизнеса
   (`Σ маржей проектов − общие = Чистая прибыль`). Просто, без искусственного размазывания.
2. **Распределение (allocation)** общих на проекты по базе (выручка / вес / время / вручную) — полный
   P&L на проект, цифры частично условны. Отложено — [ADR-009](../../90-decisions/ADR-009-multitenancy-projects.md) Шаг 3 /
   [GAP-005](../../00-meta/gaps.md#gap-005).

## Статьи по группам (наполнение)

### A — Доходы ✅ согласовано 2026-06-19

**A1 Выручка от продаж** (₽):
| Код | Статья | Прим. |
|---|---|---|
| `goods_revenue` | Выручка от реализации товара | доставка включена в цену, отдельно не выделяется; разрез — по осям (проект/клиент/SKU), не статьями |

**A2 Прочие доходы** (ниже операционной прибыли):
| Код | Статья | Валюта | Прим. |
|---|---|---|---|
| `supplier_bonus` | Бонус от поставщика | ₾ | приходит постфактум, на конкретные отгрузки не оформляется → **не уменьшает COGS**, отдельный доход |
| `vat_refund_ge` | Возврат НДС в Грузии | ₾ | возмещение груз. НДС на поставленные товары; **не привязывать** к проектам/рейсам/отгрузкам — одна большая статья |
| `inventory_surplus` | Излишки товара | — | избыток при сверке (влага/ошибки ввода): купили меньше, чем продали; детали — [GAP-065](../../00-meta/gaps.md#gap-065) |
| `interest_income` | Проценты по выданным займам | ₽/₾ | финансовый доход (симметрично B4); сторона — заёмщик |
| `other_income` | Прочие доходы | ₽/₾ | тара, штрафы в нашу пользу, разовое |

> ₾-статьи A2 пересчитываются в ₽ по курсу дня поступления.

### B — Расходы ✅ согласовано 2026-06-19 (B5 — на будущее)

**B1 Себестоимость (COGS)** — разбита для наглядности на две под-строки:
| Под-строка | Состав |
|---|---|
| Стоимость товара | закупочная цена из FIFO-партии |
| Логистика рейса | статьи `trade-cat-exptypes`: `transport`/`buyer`/`loader`/`expeditor`/`customs`/`border`/`loaderAbh`/`specStatus` |

Список статей рейса подтверждён полным.

**B2 Усышка** (одна строка):
| Код | Статья |
|---|---|
| `shrinkage` | Усышка / недостача (потери веса) |

> **Двусторонняя:** недостача → расход B2; **излишек** → доход A2 `inventory_surplus`. Выявляется
> при прохождении позиции через ноль / регулярном взвешивании. Механика и детали — [GAP-065](../../00-meta/gaps.md#gap-065),
> при донастройке складского учёта.

**B3 Операционные расходы (opex, вне рейса):**
| Код | Статья |
|---|---|
| `rent_warehouse` | Аренда склада |
| `salary` | Зарплаты |
| `bonus_staff` | Премии сотрудникам |
| `comms` | Связь / интернет |
| `rent_house` | Аренда дома |
| `meals` | Питание сотрудников |
| `fuel` | Транспорт / бензин (операционный) |
| `household` | Бытовые расходы |
| `other_opex` | Прочие расходы |

> ⚠️ `fuel` (операционный транспорт/бензин, opex) ≠ статья рейса `transport` (логистика рейса, в COGS) — не смешивать.

**B4 Финансовые расходы:**
| Код | Статья |
|---|---|
| `interest` | Проценты по займам |
| `bank_fees` | Банковские комиссии (с безналом) |

**B5 Налоги:** **НДС вшит в цену товара** (в COGS), отдельной статьёй не выделяется (возврат груз.
НДС — доход A2). Других налогов пока нет — группа заложена на будущее.

### C — Движения капитала / обязательств (вне P&L) ✅ согласовано 2026-06-19

**C1 Капитал владельца** (сторона: владелец):
| Код | Статья |
|---|---|
| `capital_contribution` | Вклад в оборот |
| `capital_withdrawal` | Изъятие из оборота |
| `dividend` | Дивиденды (из прибыли) |

**C2 Заёмные средства — мы заняли** (сторона: кредитор, **раздельно по каждому**):
| Код | Статья |
|---|---|
| `loan_principal` | Тело займа полученного (получение / возврат) |

**C3 Займы выданные — мы дали в долг** (сторона: заёмщик, **раздельно по каждому**):
| Код | Статья |
|---|---|
| `loan_given` | Тело займа выданного (выдача / возврат) — актив |

> Проценты: уплаченные → B4 `interest` (расход); полученные → A2 `interest_income` (доход).
> Кредиторы/заёмщики ведутся как сторона в settlements — **новый счёт `loan`** (рядом с
> client/supplier/partner/expense/warehouse) + справочник; баланс по каждому контрагенту.

## Справочник статей — требование к реализации (Ф-3)

1. **Справочник статей доходов/расходов расширяемый из UI** — владелец сам добавляет новые статьи
   (как `trade-cat-exptypes`, но для всех групп P&L).
2. Поля статьи: `code`, `label`, `group` (A1/A2/B1…/C3), `currency`, **`partyType`**, `active`.
3. **`partyType` фильтрует сторону при вводе:** система показывает **только релевантных**
   контрагентов/сотрудников (поступления от покупателей → только клиенты; транспорт → только
   контрагенты-перевозчики). Минимизирует ошибки при множестве контрагентов.

Значения `partyType`: `client` · `supplier` · `partner` · `lender` · `borrower` · `staff` ·
`staff:<role>` · `contragent:<cat>` · `self` · `none`.

| Статья | group | `partyType` (кого показывать) |
|---|---|---|
| `goods_revenue` | A1 | `client` |
| `supplier_bonus` | A2 | `supplier` |
| `vat_refund_ge` | A2 | `none` (государство) |
| `interest_income` | A2 | `borrower` |
| `transport` / `customs` / `border` | B1 | `contragent:<cat>` |
| `buyer` (услуги закупщика) | B1 | `staff:buyer` |
| `salary` / `bonus_staff` / `meals` | B3 | `staff` |
| `rent_warehouse` / `rent_house` | B3 | `contragent:landlord` ⏳ (нужна категория «арендодатель») |
| `fuel` | B3 | `contragent:transport` / `none` ⏳ |
| `interest` | B4 | `lender` |
| `loan_principal` | C2 | `lender` |
| `loan_given` | C3 | `borrower` |
| `capital_*` / `dividend` | C1 | `self` (владелец) |

> ⏳ детали реализации: часть статей требует **новых категорий контрагентов** (напр. арендодатель);
> точный маппинг статья→`partyType` финализируется при реализации справочника.
