# Runbook: Добавление новой роли в систему

## Когда применять

- Появляется новая функция в бизнесе, требующая отдельного исполнителя (пример: экспедитор)
- Нужно разделить существующую роль на две (пример: ops-manager → ops-manager + warehouse-manager)

## Шаги

### 1. Определить роль на бизнес-уровне

(совместно: Максим + Архитектор + CC)

- Что эта роль делает?
- Как она вписывается в существующие процессы?
- Кто исполнитель — конкретный человек, команда, или Ева?

### 2. Зафиксировать в базе знаний

- [ ] Создать `kb/30-roles/to-be/<role>.md` по [шаблону](../../00-meta/templates/role-template.md)
- [ ] Если роль уже есть в AS-IS-варианте (старая роль с новыми функциями) — создать `kb/30-roles/as-is/<role>.md`
- [ ] Обновить карту трансформации в [kb/30-roles/README.md](../../30-roles/README.md)
- [ ] Если роль изменяет функции существующих ролей — обновить их TO-BE
- [ ] Создать ADR в `kb/90-decisions/` с обоснованием

### 3. Добавить в справочник ролей

- [ ] Расширить константу `ROLES` во фронте (`trade_app_v3.jsx`)
- [ ] Если нужно — добавить новые поля в карточку сотрудника

### 4. Назначить права (RBAC)

- [ ] Обновить `kb/35-security/role-permissions.md` (матрица прав)
- [ ] Реализовать в коде: какие модули видит роль, какие операции доступны
- [ ] Обновить `kb/35-security/access-policy.md`, если меняется политика

### 5. Обучить Еву

- [ ] Создать `kb/50-agents/eva/prompts/role-<role>.md`
- [ ] Описать сценарии в `kb/50-agents/eva/scenarios/` для специфичных задач роли
- [ ] Обновить роутинг в Еве: при общении с пользователем определить, что он в этой роли

### 6. Обновить интерфейсы

- [ ] Если роль работает через веб-интерфейс — настроить отображение модулей по роли
- [ ] Если через Еву — проверить, что роль правильно определяется по telegram_chat_id или другому идентификатору
- [ ] Создать `kb/80-instructions/for-team/<role>-onboarding.md`, если применимо

### 7. Зафиксировать в реестре сотрудников

- [ ] Если есть конкретный человек — внести через интерфейс "Справочник сотрудников"
- [ ] Обновить `kb/15-team/<person>.md`, если человек уже в команде

### 8. Внести в roadmap и changelog

- [ ] Если роль внедряется этапами — добавить в [roadmap](../../65-roadmap/current.md)
- [ ] После внедрения — зафиксировать в [CHANGELOG](../../95-changelog/) дату

## Финальный чек-лист

- [ ] Роль описана в `kb/30-roles/to-be/<role>.md`
- [ ] (При необходимости) AS-IS описан
- [ ] ADR создан
- [ ] Карта трансформации обновлена
- [ ] Справочник ролей в коде расширен
- [ ] Матрица прав обновлена
- [ ] Промпт для Евы создан
- [ ] Сценарии Евы покрывают роль
- [ ] Интерфейсы обновлены (если нужно)
- [ ] CHANGELOG обновлён

## Пример: будущее добавление роли "экспедитор"

Сейчас в системе экспедитора нет. По мере проектирования он появится:
1. Описание роли в `30-roles/to-be/expeditor.md`
2. Включить в роутинг Евы (распознавать по `telegramChatId` сотрудника со staff.role = "expeditor")
3. Сценарий: экспедитор отправляет фото грузинской накладной → Ева распознаёт → подтверждение
4. Интерфейс: в `Справочнике сотрудников` есть роль `expeditor`
5. После реализации — переезд из `to-be/` в активный `30-roles/expeditor.md`
